## 三、文本过滤器审查

### 3.1 当前过滤逻辑（src/modules/fileImporter.js:22-30）

```javascript
function filterChineseChars(text) {
    if (!text || typeof text !== 'string') return '';
    const beforeLen = text.length;
    // 仅匹配 CJK 基本汉字（U+4E00 ~ U+9FA5），其余字符一律忽略
    const matches = text.match(/[\u4e00-\u9fa5]/g);
    const filtered = matches ? matches.join('') : '';
    console.log('[FileImporter] 汉字过滤：' + beforeLen + ' -> ' + filtered.length + ' 字符');
    return filtered;
}
```

### 3.2 过滤范围缺陷

| Unicode 区段 | 名称 | 当前是否覆盖 | 说明 |
| --- | --- | --- | --- |
| U+4E00–U+9FA5 | CJK 统一汉字（基本区） | ✅ 覆盖 | 常用汉字 20,902 个 |
| U+9FA6–U+9FFF | CJK 统一汉字（基本区扩展） | ❌ **未覆盖** | GB18030 / Unicode 13+ 新增汉字 |
| U+3400–U+4DBF | CJK 统一汉字扩展 A | ❌ **未覆盖** | 罕用汉字 6,582 个 |
| U+20000–U+2A6DF | CJK 统一汉字扩展 B | ❌ **未覆盖** | 罕用汉字 42,711 个 |
| U+F900–U+FAFF | CJK 兼容汉字 | ❌ **未覆盖** | 兼容汉字（部分繁体异体） |
| U+2F800–U+2FA1F | CJK 兼容汉字补充 | ❌ **未覆盖** | 兼容汉字补充 |

> [!WARNING]
> **问题 1**：`/[\u4e00-\u9fa5]/g` 范围过窄，无法匹配：
> - Unicode 13+ 新增汉字（如 U+9FA6 ~ U+9FFF）
> - 扩展 A 区汉字（U+3400–U+4DBF，部分罕用字）
> - 兼容汉字（U+F900–U+FAFF，部分繁体异体）
>
> **修复建议**：扩展正则为 `/[\u4e00-\u9fff\u3400-\u4dbf\uf900-\ufaff]/g`

### 3.3 textarea 直接输入未过滤

> [!WARNING]
> **问题 2**：用户在 textarea 中直接粘贴带标点/空格/字母的文本时，**不会经过 filterChineseChars 过滤**。只有通过 "导入文件" 按钮导入的文本才会被过滤。
>
> **renderSheet 第 604 行**：`const chars = Array.from(input).filter(c => /\S/.test(c) && c !== '\n' && c !== '\r');` — 仅过滤空白和换行，**未过滤中文标点、字母、数字**。
>
> **影响**：用户粘贴 "床前明月光，疑是地上霜。" 后，字帖渲染时 "，" 和 "。" 会被当作字符渲染进字格，破坏字帖美观。
>
> **修复建议**：在 main.js 的 generate 按钮事件或 renderSheet 入口处，对 input 调用 filterChineseChars 进行预处理。

### 3.4 字数计数器与过滤脱节

> [!NOTE]
> **问题 3**：[settings.js](file:///c:/poem2pdf/distribution/src/modules/settings.js) 的 `updateCharCounter` 统计的是 textarea.value.length，包括标点。如果未来在生成前过滤，计数器显示与实际渲染字数会不一致。
>
> **修复建议**：updateCharCounter 也应基于过滤后的字数。
