> - **不使用 Puppeteer 时，项目仍可作为纯前端 PWA 应用独立使用**，所有字帖生成、浏览器打印 PDF、PWA 离线安装、历史记录、模板库、难度评估、文件导入、AI 智能推荐等功能均正常工作。
> - **GitHub Pages 在线部署**（https://lcfactorization.github.io/calligraphy-sheet-generator/）是为了**节省服务器成本**的临时方案，并非唯一发布路径。后续可考虑部署到 Vercel / Netlify / Cloudflare Pages 等免备案海外托管平台，或自建 VPS 以支持云端 Puppeteer PDF 生成。
> - 完整的项目定位应为：**"以前端为主、本地 Node.js 服务为辅的混合架构字帖生成工具"**。前端核心功能完全离线可用，Puppeteer 服务端 PDF 是可选的增强路径。

## 2. 产品简介（复赛版 v2.7.0）

### 是什么

字帖生成器是一款**纯前端 PWA 离线应用**，基于 Vite + ES Module 工程化构建。无需服务器、无需安装、无需联网，安装到桌面/手机主屏后完全离线可用。输入汉字后自动生成带拼音标注、组词提示、笔画分解的描红字帖，支持**5 种网格类型 + 4 色线框预设 + 双轨矢量 PDF 输出**。

相比上一版复赛帖（v2.2），本次 v2.7.0 版本完成了**从"功能堆叠"到"工业级重构"的跨越**：

- **核心引擎重写**：彻底废弃 CSS 拼凑网格，升级为 viewBox 100×100 抽象坐标 + CSS mm 物理尺寸的矢量 SVG 引擎，屏幕/PDF/打印三者严格一致（误差 < 0.1mm）
- **网格类型扩展**：从 2 种（田/米）扩展到 5 种（**田字格 / 米字格 / 九宫格 / 回字格 / 拼音田字格**）
- **配色系统**：新增 4 色线框预设（传统绿 / 朱砂红 / 靛青蓝 / 墨黑），用户可一键切换
- **UI 重塑**：朱砂暖宣东方文房色系 + 320px 双栏工作台 + 图标化操作
- **数据流修复**：Puppeteer PDF 导出现在能正确应用客户端切换的网格类型与颜色预设

### 面向谁

- **中小学语文教师** — 快速生成课堂练习字帖，自定义练习内容
- **家长** — 为孩子定制课后练字纸，随时打印，保护儿童隐私
- **书法爱好者** — 自由切换 5 款开源书法字体 + 5 种网格 + 4 色线框，个性化练习
- **教育资源匮乏地区** — 无网络环境可用，服务教育公平
- **任何想写好汉字的人** — 正如作者所说："自从用了电脑，打字技术增长，但字却越来越丑"

### PWA 安装与离线使用

本作品**前端核心功能**是标准的 PWA（Progressive Web App），支持安装到桌面/手机主屏，安装后**完全离线可用**（Service Worker 预缓存全部资源含字体）。**Puppeteer 矢量 PDF 功能需要本地 Node.js 服务，在线版本不可用**。

| 平台                | 浏览器                        | 安装方法                                                              |
| ----------------- | -------------------------- | ----------------------------------------------------------------- |
| **Windows**       | Edge / Chrome（推荐）          | 地址栏右侧 ⊕ 图标 → 安装；或菜单 →「将此站点作为应用安装」                                |
| **macOS**         | Chrome / Edge              | 地址栏 ⊕ 图标 → 安装                                                     |
| **Android**       | Chrome / Edge / Firefox    | 浏览器菜单（⋮）→「添加到主屏幕」或「安装应用」                                          |
| **iOS 16.4+**     | Safari                     | 分享按钮 →「添加到主屏幕」（需 iOS 16.4+ 才支持 PWA 推送和离线）                        |
| **iOS < 16.4**    | Safari                     | 「添加到主屏幕」可创建快捷方式，离线能力有限                                            |
| **Firefox 桌面版**  | 不支持 PWA 安装                 | 可正常在线使用                                                           |
| **HarmonyOS**     | 华为浏览器 / Chrome             | 浏览器菜单 →「添加到主屏幕」（v2.8.0 已修复移动端设置模态全屏遮挡问题）                          |

**离线验证**：安装 PWA 后断开网络，按 F5 刷新页面，所有前端功能（字帖生成、拼音、笔画、浏览器打印 PDF、历史记录、模板库等）仍可正常使用。Service Worker 预缓存约 3.18 MB 资源（含字体、JS、CSS、图标）。

> [!NOTE]
> **关于 GitHub Pages 部署的说明**
>
> - GitHub Pages 是本项目当前的**在线体验入口**，主要原因是**免费、免备案、CI/CD 自动化**。
> - GitHub Pages **不支持 Node.js 后端服务**，因此在线版本只能使用浏览器打印 PDF（window.print），无法使用 Puppeteer 矢量 PDF 功能。
> - GitHub Pages 服务器位于海外，国内首次访问加载字体（~40MB）可能较慢，建议首次访问后安装 PWA 以享受 Service Worker 缓存的二次秒开体验。
> - **GitHub Pages 不是唯一发布路径**。项目源码完全开放，用户可 `git clone` 后本地运行 `npm install && npm run dev`，启动本地 Puppeteer 服务后享受完整的双轨 PDF 功能。
> - 后续可考虑部署到 Vercel / Netlify / Cloudflare Pages 等免备案海外托管平台（支持 Serverless Functions，可实现云端 Puppeteer PDF），或自建 VPS。

作为一名书法练习者，我在日常练字中遇到几个痛点：

- 市面上的字帖内容固定、无法定制
- 在线字帖工具依赖网络且常收费

**修复 7.1 — 移动端设置模态全屏遮挡问题（MatePad 反馈）**

- **用户反馈**：华为 MatePad（HarmonyOS）通过 GitHub Pages 访问时，设置中心切换网格类型/颜色后看似不生效
- **多 Agent 调查结论**：**不是性能滞后，也不是功能失效**。根因是 `settingsCenter.css` 移动端断点让 `.sc-modal` 全屏覆盖（100vh），重渲染发生在被遮挡的背景中，用户看不到
- **修复方案**：
  - 移动端模态改为底部抽屉（65vh，留 35vh 预览区）+ 减淡遮罩（0.5 → 0.25）
  - 字格容器添加视觉反馈（设置更新后紫色外框闪烁 400ms）
  - PWA 更新提示（避免旧访客持续运行老代码）

**修复 7.2 — 字数上限扩展（200 → 330 推荐 + 1000 硬上限）**

- **用户反馈**：200 字上限太少，希望增加到 330 字（30 页）
- **修复方案**：
  - textarea `maxlength` 从 200 改为 1000（浏览器原生硬上限）
  - 字数计数器三级样式：0-330 正常（灰色）/ 331-1000 警告（黄色）/ >1000 错误（红色）
  - 跨越 330 推荐上限时弹一次 toast「超过 30 页推荐上限（330 字），将生成更多页」
  - **不强制截断**：用户输入超过 330 字仍可正常生成字帖，只是会输出更多页

**修复 7.3 — 打印 PDF 性能优化（GitHub Pages 慢）**

- **用户反馈**：GitHub Pages 在线版本打印 PDF 非常慢
- **多 Agent 调查结论**：
  - 首次访问慢主因：字体串行加载（40MB 跨境下载 30-60 秒）+ alert 阻塞 + waitForStrokes 10s 超时
  - 二次访问慢主因：笔画串行加载 + SVG DOM 规模（30 页 7590 SVG / 3 万节点）
- **修复方案（短期优化，预计性能提升 60-80%）**：
  - `loadFonts()` 改并行（`Promise.all`）+ `display:swap` + 按需加载（仅加载当前选中字体）
  - `printDirect()` 中的 `alert()` 改为非阻塞 toast（复用 `.puppeteer-toast` 样式）
  - `waitForStrokes` 超时从 10s 缩短为 2s（未加载的笔画自然缺失，不阻塞打印）

### 开发踩坑与经验

#### 踩坑 1：思源宋体 zip 解压路径不一致（v2.1）

**问题**：CI 环境下载思源宋体 zip 后，硬编码路径 `/tmp/shs/SourceHanSerifSC-Regular.otf` 找不到文件。

**排查**：实际解压路径为 `/tmp/shs/OTF/SimplifiedChinese/SourceHanSerifSC-Regular.otf`，目录结构因版本而异。

**解决**：改用 `find /tmp/shs -name "SourceHanSerifSC-Regular.otf" | head -1` 动态查找。

#### 踩坑 2：PowerShell 重定向导致 UTF-16 编码（v2.1）

**问题**：从 Git 备份分支恢复 fontManager.js 时，PowerShell `>` 重定向默认保存为 UTF-16 LE（BOM: FF-FE），Vite 报 "invalid JS syntax"。

**排查**：检查文件首 4 字节 `FF-FE-2F-00` 确认为 UTF-16 LE 编码。

**解决**：改用 .NET `[IO.File]::WriteAllText` + `UTF8Encoding($false)` 重写为 UTF-8（457,850 → 228,957 bytes）。

#### 踩坑 3：GitHub Pages 部署权限（v2.1）

**问题**：CI 构建成功但部署失败，错误 `Branch "retake" is not allowed to deploy to github-pages`。

**排查**：github-pages environment 的 deployment-branch-policies 仅允许 main 分支。

**解决**：通过 `gh api --method POST .../deployment-branch-policies -f name=retake` 添加 retake 到允许列表。

#### 踩坑 4：SVG stroke-width 在 Chrome PDF 中渲染为 0 宽度（v2.5.1）

**问题**：SVG `stroke-width=2.0`（用户单位）在 PDF 中渲染为 0 宽度（PyMuPDF 分析确认：66 条边框线 width=0.0pt）。

**根因**：Chrome PDF 引擎对 SVG stroke + `preserveAspectRatio: none` + `shape-rendering: crispEdges` 的组合处理有 bug，stroke 被转为 0 宽度填充路径。

**解决**：改用**填充矩形代替 stroke**（4 个填充矩形绘制外框，N-1 个填充矩形绘制内部竖线）。填充矩形在 PDF 中始终按精确尺寸渲染，不受 shape-rendering 和 preserveAspectRatio 影响。验证结果：边框宽度 0.92pt (0.324mm)，精确渲染。

#### 踩坑 5：CSS 压缩器丢失 .fab-settings 定位属性（v2.7.0）

**问题**：Vite 的 CSS 压缩器（Lightning CSS）在合并公共属性时，丢失了 `.fab-settings` 的 `position:fixed/top/right`。

**解决**：在 `fab.css` 添加独立定位规则 `.fab-settings{position:fixed;top:20px;right:20px;z-index:9999}`，确保构建产物中规则存在。

#### 踩坑 6：Puppeteer PDF 不应用客户端网格设置（v2.6.0，严重）

**问题**：用户切换网格类型和颜色预设后，Puppeteer 方式导出的 PDF 矢量图没有任何变化。

**根因**：Puppeteer 加载全新 dist/index.html 页面，localStorage 为空；客户端未将设置传递给服务端。

**解决**：三文件协同修复（`puppeteerClient.js` 读取并发送 → `puppeteer-server.cjs` 接收并写入 Puppeteer 页面 localStorage → `puppeteer-pdf.cjs` CLI 新增参数）。

#### 踩坑 7：多 Agent 并行开发的文件冲突（v2.1）

**问题**：多个 Agent 同时修改 main.js 和 index.html 可能导致冲突。

**解决**：Agent B 只新增文件不修改现有代码（零冲突）；Agent A 和 Agent C 顺序执行（Agent C 基于 Agent A 的结果）。

## 6. 技术方案分享

### 纯前端 PWA + 矢量 PDF 双轨方案

**核心理念**：零后端依赖，保护用户隐私，离线可用。

```
用户输入汉字
    ↓
pinyin-pro 转换拼音 → cnchar 组词 → hanzi-writer 笔画
    ↓
矢量 SVG 字格引擎渲染（viewBox 100×100 + CSS mm 物理尺寸）
    ↓
方案 A：window.print() → 浏览器打印预览 → 另存为 PDF（全平台）
方案 B：Puppeteer 无头浏览器 → 矢量 PDF（文字可选可复制，应用网格/颜色）
    ↓
PWA Service Worker 缓存所有资源 → 离线可用
```

**技术亮点**：

- FontFace API 动态注册字体 + document.fonts.check() 验证加载
- FontFace 超时重试机制（5 秒超时 + 3 秒额外等待）
- JSON 解析三层防御（Connection:close + safeJsonParse + 请求去重）
- vite-plugin-singlefile 保留单 HTML 离线分发能力

### 矢量 SVG 字格引擎（v2.4.0 核心）

> [!IMPORTANT]
> v2.4.0 核心重构
>
> 彻底废弃 CSS 拼凑网格，重写为矢量 SVG 引擎，解决屏幕/PDF/打印三者不一致的根本问题。

```
┌─────────────────────────────────────────────────────────┐
│  矢量 SVG 字格引擎架构（GridEngine.js）                  │
```

### 学习闭环技术方案（v2.3.0 已精简）

> [!NOTE]
> **关于学习闭环的诚实说明**
>
> v2.1 曾实现完整的学习闭环三件套（历史记录 + 练习反馈 + 复习计划），但 v2.3.0 评估后认为反馈/复习功能让 UI 臃肿、偏离字帖生成核心，故**主动移除了练习反馈和复习计划功能**，仅保留历史记录作为基础回溯能力。
>
> 学习报告统计（reportPanel.js）仍保留，可基于历史记录展示生成次数、字数分布等统计。

```
生成字帖 → 自动保存到历史记录（localStorage, 最多 20 条）
    ↓
历史回溯 → 点击历史按钮 → 选择记录 → 一键加载重新生成
    ↓
学习报告 → 统计区块 + 柱状图 + 导出报告到剪贴板 + 重置统计数据
```

**跨模块通信**：自定义事件 `calligraphy:history-updated`、`calligraphy:settings-updated`

## 7. 社会价值分析

### 教育公平

- **无网络环境可用**：农村学校、无网络家庭、教育资源匮乏地区
- **零成本**：无需付费、无需注册、无需账号
- **隐私保护**：所有数据本地处理，不上传儿童学习数据

### 文化传承

- **汉字书写教育**：拼音+组词+笔画三位一体，辅助正确书写
- **开源字体推广**：使用霞鹜文楷、思源宋体等开源字体，推动字体生态
- **技术降低门槛**：让每个人都能自由定制练字内容

### 学习科学

- **渐进式学习**：难度评估（cnchar 笔画数 5 级星级）帮助用户选择合适内容
- **历史回溯**：自动保存最近 20 条生成记录，方便回顾练习轨迹
- **AI 智能推荐**：基于分级字库（3 级 18 分类）和预设模板的离线规则推荐
- **学习报告统计**：生成次数、字数分布等数据可视化

> [!NOTE]
> v2.1 曾实现艾宾浩斯遗忘曲线复习计划，v2.3.0 评估后移除以聚焦字帖生成核心。如评委认为该功能有价值，可在决赛阶段重新设计实现。

### 环保理念

- **按需打印**：只打印需要的练习内容，减少纸张浪费
- **数字预览**：屏幕预览确认后再打印，避免错误打印
