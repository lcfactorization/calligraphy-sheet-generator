# index.html 文件解读

> 本文档面向非技术背景用户（特别是法律从业者），用通俗语言解释字帖生成器项目根目录下 `index.html` 这个文件的作用，为什么不能直接双击打开，以及为什么绝对不能删除它。

---

## 一、为什么不能直接双击打开？

很多人看到 `index.html`，第一反应是："网页嘛，双击用浏览器打开就行了。"——这是误解。

**项目根目录的 `index.html` 不是"成品网页"，而是"源代码文件"。** 它和您在浏览器里看到的成品网页，关系就像"案件原始卷宗"和"已经整理好可以当庭出示的证据册"——中间还需要一道"整理加工"的工序。

打开它看到一片混乱（没有样式、按钮错位、字体不对、画面空白），主要有三个原因：

### 1. 它通过 ES 模块方式引入了 JavaScript

在文件末尾有这样一行：

```html
<script type="module" src="/src/main.js"></script>
```

这里的 `type="module"` 表示这是一个 **ES 模块（ES Module）**。浏览器出于安全考虑，**禁止在 `file://` 协议下加载 ES 模块**。也就是说，您双击打开文件时，浏览器地址栏开头是 `file:///C:/...`，此时这行代码会被浏览器直接拒绝执行，所有交互逻辑（生成字帖、切换主题、打印 PDF 等）全部失效。

### 2. CSS 样式是通过 JavaScript 动态注入的

入口脚本 `src/main.js` 第一行是：

```js
import './styles/main.css';
```

样式表不是直接写在 HTML 里的，而是由 JS 模块"按需引入"的。一旦 JS 模块加载失败（见上一条），样式表也不会被加载——页面就只剩下 HTML 裸奔的默认样子：黑白文字、按钮挤在一起、布局完全错乱。

### 3. 字体文件、图标等资源也依赖服务器环境

字帖生成器需要加载霞鹜文楷、文鼎楷体等多种中文字体，这些字体文件位于 `src/` 或 `public/` 目录中，引用路径是按"服务器根目录"写的（例如 `/src/...` 或 `./xxx.woff2`）。在 `file://` 协议下，浏览器无法正确解析这些路径，字体加载失败，汉字就只能用系统默认字体显示，完全不是字帖该有的样子。

### file:// 协议 vs http:// 协议

| 协议 | 含义 | 是否支持 ES 模块 | 是否支持相对路径资源 | 是否支持 CORS 字体 |
|------|------|------------------|----------------------|-------------------|
| `file://` | 直接读本地文件 | ❌ 不支持 | ⚠️ 部分支持 | ❌ 不支持 |
| `http://` | 通过本地开发服务器 | ✅ 支持 | ✅ 支持 | ✅ 支持 |

> [!NOTE]
> 简单理解：`file://` 是"自己翻抽屉找东西"，浏览器处处设防；`http://` 是"通过服务窗口领东西"，浏览器才肯放心交付。Vite 提供的 `npm run dev` 命令，就是临时搭一个这样的"服务窗口"。

## 二、index.html 的核心作用

`index.html` 是整个 Vite 工程的 **"入口点"（entry point）**。Vite 构建工具的一切工作，都是从读取这个文件开始的。

它承担两重身份：

### 身份一：开发模式下的"页面骨架"

当您运行 `npm run dev` 时，Vite 会在本地启动一个开发服务器（本项目配置端口为 **3000**，访问 `http://localhost:3000`）。Vite 会读取 `index.html`，把它作为页面骨架，并实时编译 `src/main.js` 及其引用的所有模块、样式、字体。您在浏览器里看到的效果，就是 `index.html` + `src/` 源代码动态组合的结果。

### 身份二：构建模式下的"打包蓝图"

当您运行 `npm run build` 时，Vite 会以 `index.html` 为蓝图，把 `src/` 下的所有源代码（JS 模块、CSS 样式、字体、图标等）**全部打包、压缩、内联**进一个新生成的 `dist/index.html` 文件里。这个新文件是"自包含"的成品——一个文件就能直接打开使用，不再依赖任何外部资源。

### 它定义了页面的基本骨架

`index.html` 里包含：

- `<meta charset="UTF-8">`、`<meta name="viewport">`：基础元信息
- `<title>字帖生成器</title>`：浏览器标签页标题
- `lang="zh-CN"`、`data-theme="light"`：语言和主题设置
- 浮动按钮（主题切换、打印、Puppeteer PDF、设置）
- 输入面板（字体选择、汉字输入、生成按钮）
- 页眉页脚自定义区
- 双栏工作台（侧栏 + A4 预览画布）
- 历史记录侧边栏
- 关键的挂载点和脚本入口：`<script type="module" src="/src/main.js"></script>`

> [!NOTE]
> 可以把 `index.html` 想象成一份"起诉书模板"：上面写明了案由、当事人、诉讼请求的占位位置，但具体内容要靠 `src/` 下的代码去填充。没有这份模板，后续工作就无从展开。

## 三、index.html vs 字帖生成器.html vs dist/index.html 的关系

项目里出现了三个名字相近的 HTML 文件，容易混淆。下面这张图说明了它们之间的关系：

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   【源文件层】                                                   │
│                                                                 │
│   index.html  ──┐                                               │
│                 │  +  src/  (main.js、modules/、components/…)   │
│                 │  +  styles/main.css                           │
│                 │  +  字体文件                                   │
│                 ▼                                                │
│         ┌───────────────┐                                       │
│         │  Vite 构建工具  │   ← 命令：npm run build             │
│         │  vite.config.js│                                      │
│         └───────┬───────┘                                       │
│                 │                                                │
│                 ▼                                                │
│   【成品层】                                                     │
│                                                                 │
│   dist/index.html  （单文件成品，可双击直接打开）                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
                                  ▲
                                  │  通过 iframe 引用
                                  │
┌─────────────────────────────────┴───────────────────────────────┐
│   【外壳层】                                                     │
│                                                                 │
│   字帖生成器.html  （面向最终用户的"门面"）                      │
│   ┌──────────────────────────────────────┐                      │
│   │  <iframe src="dist/index.html">      │                      │
│   │     ↑ 引用成品                       │                      │
│   │  + 加载失败时显示提示                │                      │
│   └──────────────────────────────────────┘                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 三者对比

| 文件 | 角色 | 能否双击打开 | 能否删除 |
|------|------|--------------|----------|
| `index.html`（根目录） | **源文件**，Vite 构建入口 | ❌ 显示混乱 | ❌ **绝不可删** |
| `dist/index.html` | **构建产物**，自包含成品 | ✅ 可直接打开 | ⚠️ 可删，但删后需重新 `npm run build` |
| `字帖生成器.html` | **外壳**，通过 iframe 加载成品 | ✅ 但前提是 `dist/index.html` 存在 | ❌ 不建议删 |

> [!WARNING]
> 三个文件名字都叫 `index.html` 或包含"字帖生成器"，但角色完全不同。最容易犯的错就是误以为"根目录那个 index.html 没用，删掉算了"——结果整个构建链断掉。

## 四、如何正确打开/预览项目？

以下四种方式按使用场景排列：

### 方式 1：开发模式（推荐开发/调试时使用）

```bash
npm run dev
```

- Vite 启动本地服务器（本项目端口 **3000**），自动打开浏览器
- 访问地址：`http://localhost:3000`
- 特点：修改源代码后页面自动热更新，所见即所得
- 适用场景：调试代码、查看改动效果

### 方式 2：构建 + 预览（验证成品效果）

```bash
npm run build      # 先构建，生成 dist/index.html
npm run preview    # 再预览，启动一个静态服务器托管 dist/
```

- Vite 启动一个静态服务器托管 `dist/` 目录
- 访问地址通常是 `http://localhost:4173`
- 适用场景：验证构建产物是否正常，模拟生产环境

### 方式 3：直接打开成品（最简单）

```
双击  c:\poem2pdf\distribution\dist\index.html
```

- 因为 `dist/index.html` 是 `vite-plugin-singlefile` 插件打包出的**单文件成品**，所有 JS、CSS、字体都已内联进 HTML 内部
- 无需任何服务器，双击即可打开
- 适用场景：快速演示、离线使用、发给他人查看

> [!NOTE]
> 本项目在 `vite.config.js` 中启用了 `viteSingleFile()` 插件，所以 `dist/index.html` 是真正的"单文件"——这是为什么方式 3 能成立的关键。

### 方式 4：通过外壳打开（面向最终用户）

```
双击  c:\poem2pdf\distribution\字帖生成器.html
```

- 这个外壳 HTML 通过 `<iframe src="dist/index.html">` 嵌入成品
- 它还做了容错处理：如果 1.5 秒内 iframe 没加载成功，会显示提示信息
- 适用场景：作为最终交付给用户的"入口程序"

> [!WARNING]
> 方式 4 依赖 `dist/index.html` 存在。如果 `dist/` 目录被删除或尚未构建，外壳会显示"⚠️ 无法加载字帖生成器"的提示。

## 五、为什么删除 index.html 是严重错误？

### 1. Vite 构建必须有入口 HTML

Vite 的工作流程是：**先找到 `index.html` → 解析其中的 `<script type="module">` → 顺着引用找到所有源代码 → 打包成成品**。

`index.html` 是这条流水线的"起点"。删掉它，Vite 不知道要打包什么，构建直接报错：

```
Could not resolve entry module "index.html".
```

### 2. `npm run build` 会失败

`package.json` 中的 `"build": "vite build"` 命令依赖根目录的 `index.html`。删除后这个命令将无法执行，无法生成新的 `dist/index.html`。

### 3. GitHub Pages 部署也会失败

如果项目通过 GitHub Actions 自动构建并部署到 GitHub Pages，CI 流水线中的 `npm run build` 步骤会失败，部署中断，线上页面停留在旧版本或直接 404。

### 4. 即便 `dist/index.html` 已存在，后续也无法更新

有人会想："反正 `dist/index.html` 已经在那里了，删了根目录的 `index.html` 应该没关系吧？"——这是危险的侥幸心理：

- 一旦您修改了 `src/` 下的任何代码（哪怕只是改一个汉字默认值），就需要重新 `npm run build` 才能生效
- 但构建命令已经因为缺少入口而失败
- 结果就是：**源代码改了，但成品更新不了，项目卡死在旧版本**

> [!WARNING]
> 这就像把案卷的"立案登记表"扔了——即使证据材料还在，新案子也立不进去，整个流程瘫痪。`index.html` 就是这个项目的"立案登记表"。

## 六、文件结构保护建议

为了让项目长期可维护，请遵守以下原则：

### ✅ 必须保留的文件

| 文件/目录 | 作用 | 保护级别 |
|-----------|------|----------|
| `index.html`（根目录） | Vite 构建入口源文件 | 🔴 绝不可删 |
| `src/` 目录 | 所有源代码（JS 模块、CSS、字体管理） | 🔴 绝不可删 |
| `vite.config.js` | Vite 构建配置（单文件、PWA、Tailwind 等） | 🔴 绝不可删 |
| `package.json` | 项目依赖与脚本定义 | 🔴 绝不可删 |
| `字帖生成器.html` | 面向最终用户的外壳 | 🟡 不建议删 |

### ⚠️ 可以删除但需谨慎的文件

| 文件/目录 | 说明 |
|-----------|------|
| `dist/` 目录 | 构建产物，删除后可通过 `npm run build` 重新生成。**但删除前请确认没有正在使用它的进程**（例如正在运行的 `字帖生成器.html`） |
| `node_modules/` 目录 | 第三方依赖，删除后可通过 `npm install` 重新安装 |

### 📋 日常维护清单

- [ ] 修改源代码后，记得运行 `npm run build` 重新生成 `dist/`
- [ ] 不要直接编辑 `dist/index.html`——它是构建产物，下次 `npm run build` 会覆盖
- [ ] 给最终用户分发时，分发 `字帖生成器.html` + `dist/` 目录（两者缺一不可）
- [ ] 备份项目时，至少备份 `index.html`、`src/`、`vite.config.js`、`package.json` 这四样

> [!NOTE]
> 一句话总结：**根目录的 `index.html` 是"源"，`dist/index.html` 是"流"，`字帖生成器.html` 是"渠"**。源不可断，流可重生成，渠把水送到用户田里。三者各司其职，缺一不可。
