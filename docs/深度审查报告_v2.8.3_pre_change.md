## 二、问题 1：分页错误根因分析

### 2.1 字数与页数契约

- **每页字数** = 11 行/页 × 1 字/行 = 11 字/页（[interfaces.js:119-135](file:///c:/poem2pdf/distribution/src/contracts/interfaces.js#L119)）
- **每页高度** = 11 行 × (字格 16.2mm + 辅助行 5.4mm) = 237.6mm
- **A4 可用高度** = 297mm - 上边距 29mm - 下边距 16mm = 252mm
- **section min-height** = 295mm（含 padding 8mm+5mm + 内容 282mm）
- **198 字 → 18 页** ✅

### 2.2 桌面端分页机制（正常）

[print.css:197-208](file:///c:/poem2pdf/distribution/src/styles/print.css#L197)：
```css
.print-page-section {
    display: flex !important;
    flex-direction: column;
    width: 210mm;
    min-height: 295mm;              /* ← 关键：强制每页 295mm = 11 行 */
    padding: 8mm 15.9mm 5mm 15.9mm;
    box-sizing: border-box;
    page-break-after: auto;
}
```

桌面端 Chrome 严格遵循 `min-height: 295mm`，每个 section 占满一页，11 行/页。

### 2.3 移动端分页失效根因

> [!WARNING]
> **根因定位**：v2.8.1 修复时在 [print.css:126-144](file:///c:/poem2pdf/distribution/src/styles/print.css#L126) 移动端断点中写了：
> ```css
> @media print and (max-width: 900px) {
>     .print-page-section {
>         min-height: auto !important;     /* ← 取消了 295mm 最小高度！ */
>         width: 100% !important;
>         padding: 8mm 12mm 5mm 12mm !important;  /* ← padding 也改了！ */
>     }
> }
> ```

**影响链**：
1. `min-height: auto` → section 高度 = 内容实际高度（不再强制 295mm）
2. flex column 的 `margin-top: auto`（页脚）失效 → 页脚无法推到页面底部
3. 多个 section 在一页内紧凑排列 → 14 行/页（而非 11 行/页）
4. 198 字 / 14 行 = 14.1 → 16 页（而非 18 页）

### 2.4 修复方案

**恢复移动端的 295mm 最小高度**，与桌面端完全一致：
```css
@media print and (max-width: 900px) {
    .print-page-section {
        min-height: 295mm !important;              /* ← 恢复 295mm */
        width: 210mm !important;                   /* ← 明确 210mm */
        padding: 8mm 15.9mm 5mm 15.9mm !important; /* ← 与桌面端一致 */
    }
}
```

**额外加固**：在每个 `.print-page-section` 后强制分页：
```css
.print-page-section {
    page-break-after: always !important;           /* ← 新增：段后强制分页 */
}
.print-page-section:last-child {
    page-break-after: auto !important;
}
```

## 三、问题 2：笔画 SVG 位置偏移根因分析

### 3.1 笔画 SVG 渲染流程

1. [GridEngine.js:557-559](file:///c:/poem2pdf/distribution/src/components/GridEngine.js#L557) 创建 `.grid-svg-stroke-box` 容器
2. [GridEngine.js:562-563](file:///c:/poem2pdf/distribution/src/components/GridEngine.js#L562) `loadStrokes(char, strokeBox)` 异步加载笔画 SVG
3. 笔画 SVG 插入到 `.grid-svg-stroke-box` 内部

### 3.2 布局结构

```
.grid-svg-aux-row (flex, align-items: center, height: 5.4mm)
  ├── .grid-svg-pinyin-box (width: 16.2mm, height: 5.4mm)
  │   └── svg.pinyin-four-line (viewBox 0 0 100 30)
  └── .grid-svg-stroke-box (flex: 1 1 auto, height: 5.4mm, align-items: center)
      ├── span (笔画数文字)
      └── svg.stroke-svg (width: 5mm, height: 5mm)  ← 异步插入
```

### 3.3 偏移根因

> [!WARNING]
> **根因**：[grid-svg.css:114-120](file:///c:/poem2pdf/distribution/src/styles/grid-svg.css#L114)：
> ```css
> .grid-svg-stroke-box svg,
> .grid-svg-stroke-box .stroke-svg {
>     width: 5mm;
>     height: 5mm;
>     margin-right: 0.5mm;
>     flex: 0 0 auto;
> }
> ```
> **缺失**：`vertical-align: middle` 和 `display: block`

**影响**：
- 桌面端 Chrome 对 flex + `align-items: center` 的处理较宽容，SVG 自然居中
- 移动端 HarmonyOS 浏览器对异步插入的 SVG 元素默认 `vertical-align: baseline`，导致 SVG 被推到行基线以下
- 加上 `.grid-svg-stroke-box span` 的 `line-height: 1`，SVG 被挤到下方

### 3.4 修复方案

[grid-svg.css:114-120](file:///c:/poem2pdf/distribution/src/styles/grid-svg.css#L114) 修改：
```css
.grid-svg-stroke-box svg,
.grid-svg-stroke-box .stroke-svg {
    width: 5mm;
    height: 5mm;
    margin-right: 0.5mm;
    flex: 0 0 auto;
    vertical-align: middle;     /* ← 新增：垂直居中 */
    display: block;             /* ← 新增：块级元素，避免 baseline 偏移 */
}
```

**打印时额外加固**（print.css 的 @media print）：
```css
.grid-svg-stroke-box {
    display: flex !important;
    align-items: center !important;   /* ← 强制垂直居中 */
}
.grid-svg-stroke-box svg,
.grid-svg-stroke-box .stroke-svg {
    vertical-align: middle !important;
    display: block !important;
}
```

## 四、问题 3：页眉页脚丢失 + 颜色不同步

### 4.1 页眉页脚丢失根因

> [!WARNING]
> **根因**：与问题 1 同源。`min-height: auto` 导致：
> 1. flex column 的 `margin-top: auto`（[print.css:239](file:///c:/poem2pdf/distribution/src/styles/print.css#L239)）失效
> 2. 页脚无法被推到 section 底部
> 3. 如果内容溢出 A4 页面，页脚被推到下一页或被裁剪

**修复**：同问题 1，恢复 `min-height: 295mm`。

### 4.2 页眉页脚颜色不同步根因

> [!WARNING]
> **根因**：[print.css:223](file:///c:/poem2pdf/distribution/src/styles/print.css#L223) 和 [print.css:244](file:///c:/poem2pdf/distribution/src/styles/print.css#L244) 硬编码绿色：
> ```css
> .page-section-header { color: #2E7D32; }   /* ← 硬编码传统绿 */
> .page-section-footer { color: #2E7D32; }   /* ← 硬编码传统绿 */
> ```

用户切换朱砂红 #9E2A2B 时，网格颜色变了，但页眉页脚仍是绿色。

### 4.3 修复方案

**步骤 1**：print.css 改为 CSS 变量
```css
.page-section-header { color: var(--grid-primary-color, #2E7D32); }
.page-section-footer { color: var(--grid-primary-color, #2E7D32); }
```

**步骤 2**：GridEngine.js 在 renderSheet 时设置 CSS 变量
```javascript
// 在 renderSheet 函数开头，获取 colors 后
document.documentElement.style.setProperty('--grid-primary-color', C.primary);
```

**步骤 3**：settingsCenter.js 在切换颜色预设时也同步设置
```javascript
// 在颜色预设切换的处理函数中
const colors = getActiveGridColors();
document.documentElement.style.setProperty('--grid-primary-color', colors.primary);
```

## 五、回归检测

### 5.1 v2.8.1 修复的移动端断点副作用

| v2.8.1 修复 | 副作用 | 本轮修复 |
| --- | --- | --- |
| `min-height: auto` 避免空白页 | 导致 14 行/页 + 页脚丢失 | 恢复 295mm + 段后强制分页 |
| `padding: 8mm 12mm 5mm 12mm` | 与桌面端 15.9mm 不一致 | 恢复 15.9mm |
| `display: revert` for SVG | 可能导致布局重置 | 改为显式 `display: block/flex` |

### 5.2 桌面端回归风险

- 恢复 `min-height: 295mm` 后，桌面端行为不变（原本就是 295mm）
- 新增 `page-break-after: always` 对桌面端无害（section 本身就分页）
- 笔画 SVG 加 `vertical-align: middle` 对桌面端无害（flex 已居中）

### 5.3 Puppeteer 路径影响

- Puppeteer 走 `@page margin` + `headerTemplate/footerTemplate`，不依赖 `.page-section-header/footer`
- 颜色同步修复不影响 Puppeteer（Puppeteer 的页眉页脚由 headerTemplate 控制）
- 但 Puppeteer 的 headerTemplate 也应同步颜色（可选优化）
