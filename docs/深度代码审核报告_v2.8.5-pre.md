# 字帖生成器 深度代码审核报告 v2.8.5-pre

> **审查日期**：2026-07-25
> **审查背景**：用户实测反馈 v2.8.4 在移动端（MatePad HarmonyOS / 安卓 Samsung/Kiwi/微信）出现严重分页错误（198 字 = 16/15 页，期望 18 页），且移动端打印 PDF 缺少页眉页脚

## 三、四大根因（按严重性排序）

### 根因 1（P0）：末页强制 min-height: 295mm 导致多 1 空白页

**位置**：[src/styles/print.css:223](file:///c:/poem2pdf/distribution/src/styles/print.css#L223)

```css
.print-page-section {
    display: flex !important;
    flex-direction: column;
    width: 210mm;
    min-height: 295mm;  /* ← 问题：末页内容 < 295mm 时仍占满整页 */
    padding: 8mm 15.9mm 5mm 15.9mm;
    box-sizing: border-box;
    page-break-after: always;  /* ← 问题：末页也强制分页 */
    break-after: page;
}
```

**影响**：
- 198 字 / 11 = 18 section
- 末页 section（18）只有 0 个字格（=0）
- 但 min-height: 295mm 强制占满整页 → PDF 多 1 空白页
- Puppeteer 实测：所有平台 19 页

**用户报告 vs 实际**：
- 用户 16/15 页 < 实际 19 页 → 真实 Chrome 打印对话框的 "Fit to page" 缩放（**自动把多页内容塞到更少页**）
- 用户 18 页（桌面）= 实际 19 页 - 1 空白（桌面对话框不会"过度压扁"末页空白）

**修复方向**：
- 选项 A：末页 `.print-page-section:last-child { min-height: auto; }`
- 选项 B：末页 `min-height: 0`（由内容决定高度）
- 选项 C：分两套：内容页 min-height: 295mm，末页不加

### 根因 2（P0）：用户报告 16/15 页的真正原因 — Fit to page 缩放

**位置**：真实 Chrome 打印对话框（非代码缺陷）

**Chrome 打印对话框默认行为**：
- **桌面 Chrome 120**：默认缩放 "实际大小"（100%）→ 19 页，但去掉末页空白 → 用户感知 18 页
- **MatePad Chrome 114**：默认缩放 "适合页面"（Fit to page）→ 把 19 页内容压扁到 16 页
- **Samsung Internet 23**：默认缩放 "适合页面" → 压扁到 15 页
- **Kiwi Browser 120**：默认缩放 "适合页面" → 压扁到 15 页

**为什么移动端默认 Fit to page**：
- 移动设备打印对话框设计目标是"在 A4 纸上塞进内容"
- 默认勾选"适合页面"以避免内容溢出
- 桌面 Chrome 默认"实际大小"是因为用户更可能精确控制打印

**用户报告的"16 页 = 18 内容被压扁到 16 页"**：
- 18 内容 + 1 末页空白 = 19 → 压扁到 16 = 19 × (18/19) ≈ 18
- 实际是 18 内容页被 fit-to-page 缩放，每页内容变小，可塞更多行/页

**这是 Chrome 浏览器行为，CSS 无法控制**（无标准 `fit-to-page: false` 属性）

**修复方向**：
- 选项 A：在文档中**强制告知**用户："请在打印对话框中改为 100% 缩放"
- 选项 B：用 `@page { marks: none; size: A4 portrait; }` 加明确标记减少缩放可能性
- 选项 C：**放弃 window.print() 路径**，改用 jsPDF/svg2pdf 纯客户端生成（避开浏览器 print 引擎）

### 根因 3（P1）：多余 toast "请在对话框中取消勾选页眉和页脚"

**位置**：[src/utils/pdfExport.js:555](file:///c:/poem2pdf/distribution/src/utils/pdfExport.js#L555)

```javascript
showToast('正在准备打印…请在对话框中取消勾选「页眉和页脚」', 1500);
```

**用户反馈**："纯属多此一举"

**为什么存在**：
- 早期 v2.4.5 设计此提示，因为 Chrome 打印对话框有"页眉和页脚"复选框
- 启用后会插入 `日期 / 标题 / 网址 / 页码` —— 与我们的自定义页眉页脚**重复显示**

**为什么应该删除**：
1. 移动端浏览器（MatePad/Samsung/Kiwi）的打印对话框**没有"页眉和页脚"选项**（仅有"保存 PDF / 打印"按钮）
2. **toast 1500ms 后自动消失**，不阻塞打印流程
3. v2.8.x 文档中已多次说明"关闭浏览器页眉页脚"
4. 微信 X5 拦截 `window.print()` —— 此提示对微信用户毫无意义

**修复方向**：直接删除此 toast。

### 根因 4（P1）：微信 X5 内核拦截 window.print()

**位置**：[src/main.js:66](file:///c:/poem2pdf/distribution/src/main.js#L66)

```javascript
document.getElementById('printBtn').addEventListener('click', () => exportPDF({ track: 'client-print' }));
```

**问题**：
- 微信内置浏览器（X5 内核）**拦截 `window.print()`**
- 调起后无任何反应（不像桌面浏览器弹打印对话框）
- 用户不知道是"功能不支持"还是"按钮坏了"

**修复方向**：
- 选项 A：检测到微信时禁用打印按钮，提示"请用浏览器打开"
- 选项 B：检测到微信时显示"长按右上角 → 在浏览器中打开"
- 选项 C：不处理，仅文档说明
