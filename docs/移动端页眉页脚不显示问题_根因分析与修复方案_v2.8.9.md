## 二、多 Agent 视角的根因分析

### 2.1 前端工程师视角 — CSS 层叠与打印媒体查询兼容性

**审查范围**：`src/styles/print.css`、`src/components/GridEngine.js`、`src/modules/settingsCenter.js`

#### 根因 FE-1：`display: none → display: flex !important` 切换模式在移动端打印引擎中可能失效 ⭐⭐⭐⭐⭐

**代码定位**：`src/styles/print.css`
- 第 24-30 行（屏幕态）：
  ```css
  .print-only-header, .print-only-footer,
  .print-page-section,
  .page-section-header,
  .page-section-footer { display: none; }
  ```
- 第 128-142 行（打印态，header）：
  ```css
  .page-section-header {
      display: flex !important;
      height: 8mm;
      ...
  }
  ```
- 第 165-179 行（打印态，footer）：
  ```css
  .page-section-footer {
      display: flex !important;
      height: 8mm;
      ...
  }
  ```

**机制分析**：
- 屏幕态把 `.page-section-header` / `.page-section-footer` 锁为 `display: none`
- 打印态用 `display: flex !important` 强制覆盖
- **问题**：部分移动端浏览器（华为 HarmonyOS WebView、三星 Internet、旧 Android WebView）的打印渲染管线在构建打印布局树时，对 `display: none → display: flex !important` 的运行时切换支持不一致
- 这些引擎可能在屏幕态就跳过了 `display: none` 元素的子树布局计算，打印时即使 `display` 切换为 `flex`，子元素（`<span class="ph-left">` 等）的内联布局也可能未及时重建
- **结果**：容器框被渲染（占位 8mm）但内容为空，或容器框本身被丢弃

**验证方法**：用 `?printdebug=1` 在真机打印时记录 `getBoundingClientRect()` 看 header/footer 是否有非零尺寸

#### 根因 FE-2：`var(--grid-theme-color, ...)` CSS 变量在打印上下文中可能解析失败 ⭐⭐⭐⭐

**代码定位**：
- `src/components/GridEngine.js:608-611` — 通过 `document.documentElement.style.setProperty('--grid-theme-color', colors.primary)` 写入到 `:root` 的 **inline style**
- `src/modules/settingsCenter.js:73-74` — 同样通过 inline style 写入
- `src/styles/print.css:138, 140, 175, 177` — 页眉页脚的 `color` 和 `border-color` 都依赖该变量

**机制分析**：
- inline style 写入 CSS 变量在桌面 Chrome 中稳定继承
- 但移动端打印引擎在生成打印布局树时，可能不会完整继承 `:root` 上的 inline style 变量（部分引擎对 print 上下文的变量继承做了简化）
- **fallback 链** `var(--grid-theme-color, var(--grid-primary-color, #2E7D32))` 设计正确，理论上最坏情况会 fallback 到 `#2E7D32`
- 但**若移动端引擎变量解析存在 bug，整条 fallback 链可能被跳过**，导致 `color` 和 `border-color` 解析为 `transparent` 或空值
- **结果**：即使 header/footer 容器被渲染，但**文字透明 + 边框透明**，视觉上等于"不显示"

#### 根因 FE-3：`display: flex` 容器在移动端打印引擎中可能被降级或跳过 ⭐⭐⭐

**机制分析**：
- `.page-section-header` / `.page-section-footer` 都是 `display: flex`
- 桌面 Chromium 的 print path 完整支持 flex
- 但移动端 HarmonyOS / 三星浏览器的打印渲染层可能基于较旧的 Chromium 或自有引擎，对 print 上下文的 flex 支持不完整
- **结果**：flex 容器在打印时被当作 `display: none` 或 `display: block` 处理，子元素 `<span>` 的 `flex: 1` 失效导致溢出 `overflow: hidden` 被裁切

#### 根因 FE-4：缺少 `print-color-adjust: exact` 导致颜色/边框被丢弃 ⭐⭐⭐

**代码定位**：`src/styles/print.css`
- 第 205-215 行只对**字格 SVG 元素**设置了 `print-color-adjust: exact !important`
- **页眉页脚的文字颜色和边框**没有显式设置 `print-color-adjust: exact`

**机制分析**：
- 移动端打印引擎默认会"优化"打印输出，丢弃彩色背景/边框以节省墨水
- 即使颜色用 CSS 变量解析成功，没有 `print-color-adjust: exact` 也可能被引擎丢弃
- **结果**：文字颜色变白/变灰，边框消失

### 2.2 网页工程师视角 — window.print() 时序与事件竞态

**审查范围**：`src/utils/pdfExport.js` 的 `printDirect()` 函数（第 344-580 行）

#### 根因 WE-1：`focus` 事件在移动端打印流程中可能误触发 cleanup ⭐⭐⭐⭐⭐

**代码定位**：`src/utils/pdfExport.js:517`
```js
window.addEventListener('focus', cleanup);
```

**误触发场景**：
1. **场景 A**：Android 系统打印预览对话框是一个独立的 Activity/WebView，弹出时会夺取 window 焦点；当用户在打印预览中操作（点击"保存为 PDF"/"取消"）后，系统把焦点交还给原 window → `focus` 事件触发 → cleanup 执行
2. **场景 B**：HarmonyOS 浏览器在打印预览加载完成时，会自动 window.focus() 自身以使打印快捷键生效 → `focus` 事件触发 → cleanup 执行
3. **场景 C**：用户在打印预览中切换"纸张方向"/"页边距"等选项时，部分机型会重新激活原 window 的 focus 事件

**时序图**：
```
[用户点击打印按钮]
        ↓
[printDirect() 构建带页眉页脚的 .print-page-section DOM]
        ↓
[window.print() 异步调用，立即返回]
        ↓
[系统打印预览对话框弹出，夺取焦点]
        ↓
[用户在预览中操作 / 预览自动聚焦]
        ↓
[focus 事件回到 window → cleanup 触发]
        ↓
[wrapper 销毁，子元素移回 #grid-container（屏幕态，无页眉页脚）]
        ↓
[打印管线异步读取 DOM → 读到屏幕态 DOM → 页眉页脚缺失]
```

#### 根因 WE-2：`visibilitychange` 事件在移动端打印流程中可能误触发 cleanup ⭐⭐⭐⭐

**代码定位**：`src/utils/pdfExport.js:512-514, 516`
```js
const onVisible = () => {
    if (document.visibilityState === 'visible') cleanup();
};
document.addEventListener('visibilitychange', onVisible);
```

**误触发场景**：
1. **场景 A**：Android 打印预览是一个独立 Tab/Activity，打开时原 Tab 进入 hidden 状态；用户关闭预览后原 Tab 回到 visible → `visibilitychange` 触发 → cleanup
2. **场景 B**：HarmonyOS 浏览器打印预览是模态弹窗，弹窗显示时 document.visibilityState 短暂变为 hidden 再变回 visible → 触发 cleanup
3. **场景 C**：用户在打印预览中切换到其他 App（如文件管理器选保存位置）再返回，visibilityState 经历 visible → hidden → visible → 触发 cleanup

**关键问题**：`onVisible` 只检查 `visibilityState === 'visible'`，**没有判断 print 状态是否已结束**，任何 hidden → visible 的切换都会触发 cleanup

#### 根因 WE-3：v2.8.7 三事件驱动可能比 v2.8.6 setTimeout 1秒引入了新的竞态风险 ⭐⭐⭐⭐

**v2.8.6 旧方案**：
```js
setTimeout(cleanup, 1000);
```
- 缺点：1 秒太短，移动端打印管线可能还没读完 DOM
- 但 **时序确定**：只在 print() 调用后 1 秒触发一次

**v2.8.7 新方案**：
```js
window.addEventListener('afterprint', cleanup);
document.addEventListener('visibilitychange', onVisible);
window.addEventListener('focus', cleanup);
let fallbackTimer = setTimeout(cleanup, 120000);
```
- 优点：理论上更健壮
- 缺点：**3 个事件中任何一个先触发都会执行 cleanup**，而 `focus` 和 `visibilitychange` 在移动端打印预览**弹出/操作/关闭**的整个生命周期中都可能被多次触发
- 即使有 `let cleaned = false` 幂等保护，**第一次误触发就足以让 DOM 被销毁**
- **结论**：v2.8.7 的方案在某些移动端场景下比 v2.8.6 **更危险**

#### 根因 WE-4：缺少 `matchMedia('print')` 精确感知打印状态 ⭐⭐⭐

**机制分析**：
- 现代浏览器支持 `window.matchMedia('print').addEventListener('change', listener)`
- 该 API 在打印开始时 `matches = true`，打印结束时 `matches = false`
- **这是唯一能精确感知"打印流程是否结束"的 API**
- 当前代码没有使用该 API，而是用 `focus` / `visibilitychange` 这些**与打印状态间接相关**的事件

| 1 | WE-1：`focus` 事件误触发 cleanup | ⭐⭐⭐⭐⭐ |
| 2 | WE-2：`visibilitychange` 事件误触发 cleanup | ⭐⭐⭐⭐ |

### 2.3 移动端开发工程师视角 — 打印框架几何与渲染机制

**审查范围**：Android PrintDocumentAdapter / HarmonyOS PrintManager / 三星 Internet 打印层

#### 根因 ME-1：Android PrintDocumentAdapter 在 CSS @page margin 之外叠加系统打印机边距 ⭐⭐⭐⭐

**机制分析**：
- CSS `@page { margin: 10mm }` 设定的是"页面内容区"边距
- Android PrintDocumentAdapter 在生成 PrintDocument 时，会**额外**叠加系统打印机的硬件边距（通常 5-10mm）
- 实际可打印区高度 = 297mm - 2×10mm（CSS）- 2×5~10mm（硬件）= **267~277mm**
- 当前 section 高度 = 277mm，**已经处于临界值**
- 若硬件边距为 10mm，实际可打印区只有 257mm，footer（最后 8mm）会被裁切到第二页或完全丢失

**数值估算**：
- A4 高度 297mm
- CSS @page margin 10mm × 2 = 20mm
- Android 系统打印机边距 5~10mm × 2 = 10~20mm
- 实际可打印区高度 = 297 - 20 - 10~20 = **257~267mm**
- 当前 section 高度 277mm **超出实际可打印区 10~20mm**
- footer 8mm **必被裁切**

#### 根因 ME-2：HarmonyOS 华为浏览器"适应页面"缩放策略 ⭐⭐⭐⭐

**机制分析**：
- 华为浏览器打印预览默认开启"适应页面"缩放（类似 Chrome 的 "Fit to page"）
- 当 section 高度 277mm 略大于实际可打印区时，缩放策略会按比例缩小整个 section（如缩到 95%）
- 缩放后：
  - header 8mm → 7.6mm
  - content 261mm → 247.9mm
  - footer 8mm → 7.6mm
  - 总计 263.1mm（仍可能超出实际打印区）
- **更糟的是**：缩放是整页缩放，但**移动端渲染管线可能只对内容区缩放，对 header/footer 这种固定高度子元素不缩放或直接丢弃**

#### 根因 ME-3：三星浏览器"默认边距"策略导致打印区不足 ⭐⭐⭐

**机制分析**：
- 三星 Internet 浏览器打印预览的"边距"选项默认是"默认"（不是"无"也不是"最小"）
- "默认"边距通常为 10-15mm
- 在 CSS @page margin 10mm 基础上再叠加 10-15mm → 实际可打印区高度 = 297 - 20 - 20~30 = **247~257mm**
- 当前 section 277mm **严重超出**，footer 必丢失

#### 根因 ME-4：移动端打印框架对 `position: relative` 容器的特殊处理 ⭐⭐⭐

**代码定位**：`src/styles/print.css:106`
```css
.print-page-section {
    display: block !important;
    width: 190mm;
    height: 277mm;
    position: relative;   /* ← 此处 */
    ...
}
```

**机制分析**：
- 某些移动端打印引擎会把 `position: relative` 元素视为"已布局"状态，不再重新计算子元素的文档流位置
- 这可能导致子元素 header（位于 section 顶部）和 footer（位于 section 底部）的文档流位置错乱
- 桌面 Chrome 没有这个问题，但移动端引擎可能有

### 2.4 代码分析师视角 — DOM 生命周期与逻辑一致性

**审查范围**：`src/utils/pdfExport.js` 的 `printDirect()` 全函数

#### 根因 CA-1：DOM 创建顺序正确，无异常分支（确认排除）✅

**代码定位**：`src/utils/pdfExport.js:434-487`

**审查结论**：
- 第 443-449 行：header 创建后 `section.appendChild(header)` ✅
- 第 451-476 行：content 创建后 `section.appendChild(content)` ✅
- 第 478-484 行：footer 创建后 `section.appendChild(footer)` ✅
- 第 486 行：`wrapper.appendChild(section)` ✅
- 第 489 行：`grid.parentNode.insertBefore(wrapper, grid)` ✅
- **DOM 创建与附加顺序完全正确**，没有任何 continue/break/return 跳过 footer
- 此路径**不是根因**

#### 根因 CA-2：cleanup 函数幂等保护有效，但无法防止"第一次误触发" ⭐⭐⭐⭐

**代码定位**：`src/utils/pdfExport.js:492-511`

**审查结论**：
- `let cleaned = false` 标志位确实能防止重复执行
- 但 **第一次误触发（如 focus 事件）就足以销毁 wrapper**，幂等保护只能防止后续重复销毁
- cleanup 执行后：
  - `pages.flat().forEach(c => grid.appendChild(c))` 把字格行移回 `#grid-container` ✅
  - `wrapper.remove()` 销毁带页眉页脚的 wrapper ✅
  - **此时打印管线若再读 DOM，读到的是屏幕态 `#grid-container`，无页眉页脚** ❌

#### 根因 CA-3：`requestAnimationFrame` 双层包裹可能给浏览器重排机会 ⭐⭐⭐

**代码定位**：`src/utils/pdfExport.js:559-570`

```js
requestAnimationFrame(() => {
    requestAnimationFrame(() => {
        try {
            window.print();
        } catch (e) { ... }
    });
});
```

**审查结论**：
- 双层 RAF 的初衷是保持在用户手势上下文内调用 print()
- **副作用**：两个 RAF 帧之间浏览器有机会进行 style 重计算和 layout 重排
- 如果在第一个 RAF 帧后，某个 CSS 规则的 media query 状态发生变化（如 `matchMedia('print')` 提前变化），可能导致 layout 在 print() 调用前就被重新计算
- 这本身不一定是根因，但**可能与 FE-1（display 切换失效）协同**：浏览器在 RAF 间隙重排时把 `display: none` 的 header/footer 子树标记为"无需重渲染"

#### 根因 CA-4：二次打印时事件监听器残留风险 ⭐⭐⭐

**代码定位**：`src/utils/pdfExport.js:515-519`

**审查结论**：
- cleanup 中调用了 `removeEventListener` 解绑三个事件
- **但**：如果第一次 printDirect() 的 cleanup 因 120s 超时触发（即 afterprint/focus/visibilitychange 都没触发），监听器在 cleanup 内被移除
- 若用户在 120s 内再次点击打印，第二次 printDirect() 会注册**新的**三组监听器
- 第一次的监听器若已被 cleanup 移除则无影响；若**第一次的 cleanup 还没触发**（极端情况），则两组监听器并存，事件触发时两次 cleanup 都会尝试执行
- `let cleaned = false` 是函数作用域变量，**两个独立的 printDirect() 调用有各自独立的 cleaned 变量**
- 第二次 cleanup 会尝试 `wrapper.remove()` 但 wrapper 已被第一次 cleanup 销毁 → 抛错
- **此为低概率但存在的风险**

## 三、综合根因确认（4 视角交叉验证）

> 4 个 agent 的分析在以下根因上**收敛一致**：

### 🎯 主根因（必修复，按优先级排序）

#### 🔴 P0-1：cleanup 提前触发导致 DOM 被销毁（WE-1 + WE-2 + CA-2 收敛）

**置信度**：⭐⭐⭐⭐⭐（4 个 agent 中 3 个独立得出此结论）

**根因机制**：
- v2.8.7 新增的 `focus` 和 `visibilitychange` 事件监听器在移动端打印预览的整个生命周期中**可能多次误触发**
- 任何一次误触发都会执行 cleanup → wrapper 被销毁 → 字格行移回 `#grid-container` → 打印管线异步读取 DOM 时读到屏幕态（无页眉页脚）
- 即使 `let cleaned = false` 有幂等保护，**第一次误触发就足够致命**

**为何 v2.8.7 分页正常但页眉页脚缺失**：
- 分页由 `.print-page-section` 的 `break-after: page` 控制，**这部分 CSS 在 cleanup 销毁 wrapper 之前可能已经被打印管线读取并缓存**
- 页眉页脚是 wrapper 内部子元素，**需要打印管线在渲染阶段读取完整 DOM**
- 时间差：cleanup 销毁 wrapper 的时机晚于分页 CSS 读取，早于子元素渲染 → 分页正常但页眉页脚缺失

#### 🔴 P0-2：`display: none → display: flex !important` 切换在移动端打印引擎中可能失效（FE-1 + FE-3 + CA-3 收敛）

**置信度**：⭐⭐⭐⭐（前端 + 代码分析师得出）

**根因机制**：
- 屏幕态 `.page-section-header { display: none }` 让浏览器跳过该子树的布局计算
- 打印态 `display: flex !important` 切换需要浏览器重新构建布局树
- 移动端某些打印引擎对这种运行时 display 切换支持不完整
- 双层 `requestAnimationFrame` 给了浏览器重排机会，可能在此间隙把 header/footer 标记为"无需重渲染"

#### 🔴 P0-3：缺少 `print-color-adjust: exact` 导致颜色/边框被丢弃（FE-4 单独发现，但与 ME-2 协同）

**置信度**：⭐⭐⭐⭐

**根因机制**：
- 移动端打印引擎默认"优化"彩色输出
- 当前 CSS 只对字格 SVG 设置了 `print-color-adjust: exact`
- 页眉页脚的文字颜色和边框没有此设置 → 可能被引擎丢弃
- 与 ME-2（HarmonyOS 缩放）协同：缩放 + 颜色丢弃 = 页眉页脚视觉上完全消失

## 四、修复方案（按优先级排序）

### 4.1 P0 修复方案（必做，针对主根因）

#### 方案 P0-1：重写 cleanup 事件链，引入 `matchMedia('print')` 精确感知

**目标**：消除 focus/visibilitychange 误触发，只在打印流程真正结束时执行 cleanup

**修改文件**：`src/utils/pdfExport.js` 第 491-519 行

**修改思路**：
1. **删除** `window.addEventListener('focus', cleanup)` 和 `document.addEventListener('visibilitychange', onVisible)`
2. **新增** `window.matchMedia('print').addEventListener('change', onPrintChange)` 监听打印状态
3. **保留** `window.addEventListener('afterprint', cleanup)` 作为桌面端主要触发器
4. **保留** 120s 兜底超时
5. **新增** 移动端专用兜底：`afterprint` + `matchMedia('print')` 都未触发时，用 `pagehide` 事件兜底

**参考代码**（仅方案，不实际修改）：
```js
// RC1 修复 v2：精确感知打印状态，删除误触发的 focus/visibilitychange
let cleaned = false;
const cleanup = () => {
    if (cleaned) return;
    cleaned = true;
    console.log('[pdfExport] cleanup 开始');
    removedBreakRows.forEach(r => {
        r.classList.add('page-break');
        r.setAttribute('data-page-break', '');
    });
    pages.flat().forEach(c => grid.appendChild(c));
    if (wrapper.parentNode) {
        wrapper.parentNode.insertBefore(grid, wrapper);
        wrapper.remove();
    }
    window.removeEventListener('afterprint', cleanup);
    window.removeEventListener('pagehide', cleanup);
    if (printMediaQuery) {
        printMediaQuery.removeEventListener('change', onPrintChange);
    }
    if (fallbackTimer) { clearTimeout(fallbackTimer); fallbackTimer = null; }
    console.log('[pdfExport] cleanup 完成');
};

// afterprint：桌面 Chrome 主要触发器，移动端部分浏览器也支持
window.addEventListener('afterprint', cleanup);

// matchMedia('print')：精确感知打印状态变化
// 打印开始时 matches=true，打印结束时 matches=false
let printMediaQuery = null;
try {
    printMediaQuery = window.matchMedia('print');
    const onPrintChange = (ev) => {
        // matches=false 表示打印流程结束（用户关闭打印预览或完成打印）
        if (!ev.matches) cleanup();
    };
    if (printMediaQuery.addEventListener) {
        printMediaQuery.addEventListener('change', onPrintChange);
    } else if (printMediaQuery.addListener) {
        // Safari < 14 兼容
        printMediaQuery.addListener(onPrintChange);
    }
} catch (e) {
    console.warn('[pdfExport] matchMedia(print) 不支持，回退到 pagehide', e);
}

// pagehide：移动端极端兜底（用户切到后台、关闭页面等）
window.addEventListener('pagehide', cleanup);

// 120s 超长兜底（仅作内存回收）
let fallbackTimer = setTimeout(cleanup, 120000);
```

    // 根因：v2.8.7 的 focus/visibilitychange 在移动端打印预览生命周期中会误触发 cleanup
    // 导致 wrapper 被提前销毁，打印管线读到屏幕态 DOM（无页眉页脚）
    let cleaned = false;
    const cleanup = () => {
        if (cleaned) return;
        cleaned = true;
        console.log('[pdfExport] cleanup 开始');
        removedBreakRows.forEach(r => {                   // RC4：恢复分页标记
            r.classList.add('page-break');
            r.setAttribute('data-page-break', '');
        });
        pages.flat().forEach(c => grid.appendChild(c));
        if (wrapper.parentNode) {
            wrapper.parentNode.insertBefore(grid, wrapper);
            wrapper.remove();
        }
        window.removeEventListener('afterprint', cleanup);
        window.removeEventListener('pagehide', cleanup);
        if (printMediaQuery && onPrintChange) {
            try {
                if (printMediaQuery.removeEventListener) {
                    printMediaQuery.removeEventListener('change', onPrintChange);
                } else if (printMediaQuery.removeListener) {
                    printMediaQuery.removeListener(onPrintChange);
                }
            } catch (e) { /* 忽略 */ }
        }
        if (fallbackTimer) { clearTimeout(fallbackTimer); fallbackTimer = null; }
        console.log('[pdfExport] cleanup 完成');
    };

    // afterprint：桌面 Chrome 主要触发器，移动端部分浏览器也支持
    window.addEventListener('afterprint', cleanup);

    // matchMedia('print')：精确感知打印状态变化
    // 打印开始时 matches=true，打印结束时 matches=false（用户关闭预览或完成打印）
    let printMediaQuery = null;
    let onPrintChange = null;
    try {
        printMediaQuery = window.matchMedia('print');
        onPrintChange = (ev) => {
            console.log('[pdfExport] matchMedia(print) change:', ev.matches);
            // matches=false 表示打印流程结束
            if (!ev.matches) cleanup();
        };
        if (printMediaQuery.addEventListener) {
            printMediaQuery.addEventListener('change', onPrintChange);
        } else if (printMediaQuery.addListener) {
            // Safari < 14 兼容
            printMediaQuery.addListener(onPrintChange);
        }
    } catch (e) {
        console.warn('[pdfExport] matchMedia(print) 不支持，仅依赖 afterprint + pagehide', e);
    }

    // pagehide：移动端极端兜底（用户切到后台、关闭页面等）
    window.addEventListener('pagehide', cleanup);

    // 120s 超长兜底（仅作内存回收，绝不影响打印管线读取窗口）
    let fallbackTimer = setTimeout(cleanup, 120000);
