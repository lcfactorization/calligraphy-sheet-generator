## 〇、v2.9.6 紧急修复（最新版本）

### 0.1 P0 硬伤：引导 spotlight 高亮控件位置错乱到对角

#### 用户反馈
> "启动程序时候的导航功能，介绍控件的位置和功能时，会把高亮出来的控件位置移到相反的方向，请务必在不同的操作系统平台、浏览器上做更加认真细致的测试，确保介绍不同控件的时候，点亮的控件的确是在它应该出现的位置，而不是被移动到对角或其它错误位置上点亮。"

#### 现象
- 启动时的"新手引导"功能，介绍某个控件时，被高亮的控件位置会被错误地移到屏幕对角方向。
- 影响所有 5 步引导（设置中心 / 打印 / 侧栏 / 主题 / Puppeteer），桌面端和移动端均可复现。

#### 根因分析
- 位置：`src/styles/onboarding.css` 的 `.ob-spotlight` 规则
- 错误代码（v2.9.5）：
  ```css
  .ob-spotlight {
      position: relative !important;   /* ⚠️ 罪魁祸首 */
      z-index: 10011 !important;
      box-shadow: 0 0 0 9999px rgba(0,0,0,.7) !important;
  }
  ```
- 定位语义冲突链：
  1. FAB 类控件（`.fab-settings` / `.fab-theme` / `.fab-print` / `.fab-puppeteer` / `.history-fab`）原本 `position: fixed`，其 `top/right/bottom/left` 是**视口坐标**。
  2. `.ob-spotlight` 用 `position: relative !important` 强制覆盖后，FAB 退回 `static` 流末尾（视觉上跌到文档末尾），再叠加 `right: 24px` —— 但 relative 的 `right` 是**反向相对偏移**（向左偏移 24px）。
  3. 最终视觉：FAB 跌到文档末尾后向左偏移 24px，呈现"对角位置"的错乱效果。
- z-index 也失效：`position: relative` 本想让 z-index 生效，但破坏了 FAB 的 fixed 定位语义，得不偿失。

#### 修复方案对比

| # | 方案 | 优点 | 缺点 | 评估 |
|---|------|------|------|------|
| 1 | 移除 `.ob-spotlight` 的 `position: relative !important`，FAB 保持 fixed | 最小改动，根因修复 | 非 FAB static 目标的 z-index 仍需处理 | ✅ 采纳（核心） |
| 2 | 改用 `outline` + 半透明 overlay 实现高亮 | 不依赖 box-shadow，定位无侵入 | 改动量大，需重写 spotlight 机制 | ❌ 改动过大 |
| 3 | 给每个 FAB 单独写 `.fab-xxx.ob-spotlight` 规则 | 精确控制 | 维护成本高 | ✅ 部分采纳（border-radius 分设） |
| 4 | 用 JS 动态读 rect 设置 inline style | 灵活 | 性能差、维护复杂 | ❌ 不必要 |

**最终方案**：组合 1 + 3，按形状分设 border-radius，对非 FAB static 目标才加 relative。

#### 修复后代码
```css
/* v2.9.6 修复：不要写 position: relative/fixed !important
   —— 会破坏 FAB 的 position:fixed 定位语义 */
.ob-spotlight {
    z-index: 10011 !important;
    box-shadow: 0 0 0 9999px rgba(0, 0, 0, 0.7) !important;
    transition: box-shadow 0.3s var(--ease-out-soft) !important;
}

/* FAB 保留 50% 圆角 */
.fab-settings.ob-spotlight,
.fab-theme.ob-spotlight,
.fab-print.ob-spotlight,
.fab-puppeteer.ob-spotlight,
.history-fab.ob-spotlight {
    border-radius: 50% !important;
}

/* 非 FAB 的 static 目标才加 relative（z-index 才生效） */
.ob-spotlight:not(.fab-settings):not(.fab-theme):not(.fab-print):not(.fab-puppeteer):not(.history-fab) {
    position: relative !important;
    border-radius: 10px !important;
}

/* 防御：拖拽时 .dragging 不要覆盖 spotlight 阴影 */
.fab-settings.ob-spotlight.dragging,
.fab-theme.ob-spotlight.dragging,
.fab-print.ob-spotlight.dragging,
.fab-puppeteer.ob-spotlight.dragging,
.history-fab.ob-spotlight.dragging {
    box-shadow: 0 0 0 9999px rgba(0, 0, 0, 0.7) !important;
}
```

## 三、方案对比与选型

### 3.1 移动端新用户友好性（小组2 评估）

| 方案 | 实现复杂度 | 用户打扰度 | 老用户影响 | 风险 | 评分 |
|------|-----------|-----------|-----------|------|------|
| **A. 滚动时箭头提示** | 中（监听 scroll + getBoundingClientRect） | 低（仅滚动时显示） | 无（可关闭） | FAB 是 fixed 始终可见，提示几乎不触发 | ⭐⭐⭐ |
| **B. 半透明闪烁边角** | 中（fixed 定位 + opacity 动画） | 高（持续闪烁干扰） | 有（除非加开关） | 视觉污染，违背"核心区域不变"原则 | ⭐⭐ |
| **C. 首次使用引导浮层** | 高（5 步引导 + localStorage） | 仅首次（可跳过） | 无（老用户不弹窗） | 实现量大但可控 | ⭐⭐⭐⭐⭐ |
| **D. 底部工具栏收拢** | 高（重构 FAB 布局） | 中（始终显示底部栏） | 有（布局变化大） | 与 v2.9.4 重排冲突 | ⭐⭐ |
| **E. 抽屉式菜单** | 高（核心按钮 + 抽屉） | 中（需点击展开） | 有（操作路径变长） | 改动量大 | ⭐⭐⭐ |

**选型**：**C + A 组合**（首次使用引导为主 + 滚动边角提示为辅）
- 首次访问用引导浮层一次性介绍 5 个核心控件
- 老用户用滚动边角提示（虽然 FAB 是 fixed 几乎不触发，但作为兜底）
- 复用现有 `.puppeteer-toast` 和 `.sc-restart-ob` 样式，零新增依赖

### 3.2 桌面端拖拽（小组3 评估）

| 方案 | 实现复杂度 | click 冲突 | 移动端影响 | 风险 | 评分 |
|------|-----------|-----------|-----------|------|------|
| **A. 原生 JS + Mouse Events** | 中 | 需处理（位移阈值） | 无（仅桌面端启用） | 低 | ⭐⭐⭐⭐⭐ |
| **B. 原生 JS + Pointer Events** | 中 | 需处理（位移阈值） | 无（matchMedia 检测） | 低（统一鼠标/触摸） | ⭐⭐⭐⭐⭐ |
| **C. react-dnd / sortablejs** | 低（库封装） | 库已处理 | 需引入依赖 | 高（增加 bundle 体积，违背"零依赖"原则） | ⭐⭐ |
| **D. HTML5 Drag API** | 低 | 无 click 冲突 | 桌面端专用 | 中（视觉反馈差，需自定义 ghost） | ⭐⭐⭐ |

**选型**：**B（Pointer Events）**
- 统一处理鼠标和触摸（虽然移动端不启用，但代码统一）
- 5px 位移阈值区分 click/drag
- `{ capture: true, once: true }` 拦截拖拽后的 click
- 8px 网格吸附 + 边界约束 + localStorage 持久化

### 3.3 跨平台脚本（小组1 评估）

| 方案 | 实现复杂度 | 风险 | 评分 |
|------|-----------|------|------|
| **A. 补齐 .sh 端口检查（仿 .ps1）** | 中 | 低 | ⭐⭐⭐⭐⭐ |
| **B. 用 Node.js 重写统一入口** | 高 | 中（破坏现有 .bat/.ps1/.sh 三件套） | ⭐⭐⭐ |
| **C. 跨平台 npm script** | 低 | 高（无法处理端口检查交互） | ⭐⭐ |

## 四、详细修复过程

### 4.1 小组1：跨平台启动脚本修复

#### 4.1.1 Puppeteer 版本一致性检查

| 文件 | 字段 | 值 | 结论 |
|---|---|---|---|
| `package.json` | `"puppeteer": "^23.0.0"` | 允许 ≥23.0.0 且 <24.0.0 | 符合 semver |
| `package-lock.json` | `"node_modules/puppeteer": { "version": "23.11.1" }` | 实际锁定 23.11.1 | 无退回 |
| `package-lock.json` | `"node_modules/puppeteer-core": { "version": "23.11.1" }` | 子依赖一致 | 无漂移 |

**结论**：`^23.0.0` 允许 23.11.1，符合 semver，**无版本退回，无需修改**。

#### 4.1.2 `启动Puppeteer.sh` 修复（37 → 133 行）

**核心变更**：

1. **shebang 跨平台**：`#!/bin/bash` → `#!/usr/bin/env bash`
2. **`set -u`**：未定义变量报错（不加 `set -e`，保留端口选择交互）
3. **`node`/`nodejs` 双兜底**：
   ```bash
   NODE_BIN=""
   if command -v node &> /dev/null; then
       NODE_BIN="node"
   elif command -v nodejs &> /dev/null; then
       NODE_BIN="nodejs"
   else
       echo "[X] 未找到 Node.js，请安装: https://nodejs.org/"
       read -rp "按回车退出..."
       exit 1
   fi
   ```
4. **端口占用检查（三工具链自动选择）**：
   ```bash
   if command -v lsof &> /dev/null; then
       if lsof -i:"$PORT" &> /dev/null; then
           PORT_OCCUPIED=true
           PORT_PID="$(lsof -i:"$PORT" -t 2>/dev/null | head -n1)"
       fi
   elif command -v ss &> /dev/null; then
       # ...
   elif command -v netstat &> /dev/null; then
       # ...
   fi
   ```
5. **进程名反查（绕过 Linux sudo 限制）**：
   ```bash
   PORT_COMM="$(ps -p "$PORT_PID" -o comm= 2>/dev/null | head -n1)"
   ```
6. **服务退出后暂停**（仿 .ps1）：
   ```bash
   EXIT_CODE=$?
   if [ "$EXIT_CODE" -ne 0 ]; then
       echo "[错误] 服务异常退出，退出码: $EXIT_CODE"
   fi
   read -rp "服务已停止，按回车退出..."
   ```

#### 4.1.3 跨平台兼容性矩阵

| 平台 | 启动脚本 | Node.js 检查 | 构建产物 | Puppeteer | 端口检查 | 退出暂停 |

#### 4.2.3 关键技术点

1. **可见性检查**（桌面端跳过 `display:none` 的侧栏开关）：
   ```js
   function isElementVisible(el) {
       if (!el) return false;
       const rect = el.getBoundingClientRect();
       if (rect.width === 0 || rect.height === 0) return false;
       const cs = getComputedStyle(el);
       if (cs.display === 'none' || cs.visibility === 'hidden' || cs.opacity === '0') return false;
       return true;
   }
   ```
2. **spotlight 高亮技巧**：`box-shadow: 0 0 0 9999px rgba(0,0,0,0.7)` 形成全屏遮罩，目标元素本身保持可见
3. **移动端气泡定位**：`getBoundingClientRect()` 计算目标位置，气泡贴近目标 + 边界检查（不超出视口 12px）
4. **桌面端气泡居中**：`@media (min-width: 681px)` 强制 `top:50%; left:50%; transform:translate(-50%,-50%)`，隐藏箭头
5. **滚动边角提示**：`IntersectionObserver` 检测核心控件是否在视口，不在则显示 `pulse` 动画的箭头按钮
6. **打印时隐藏**：`@media print` 对 `.ob-spotlight/.ob-bubble/.ob-hint/#onboarding-root` 设 `display:none`

### 4.3 小组3：桌面端 FAB 拖拽

#### 4.3.1 新增文件

- `src/modules/fabDrag.js`（240 行）：Pointer Events + 5px 阈值 + 8px 网格吸附 + localStorage 持久化

#### 4.3.2 关键技术点

1. **click 与 drag 冲突处理**（5px 阈值）：
   ```js
   function onPointerMove(e) {
       const dx = e.clientX - st.startX;
       const dy = e.clientY - st.startY;
       if (!st.isDragging) {
           if (Math.hypot(dx, dy) < DRAG_THRESHOLD) return; // 仍未超过阈值
           st.isDragging = true;
           el.classList.add('dragging');
           applyLeftTop(el, st.originLeft, st.originTop); // 首次超过阈值才切换定位
       }
       // ...
   }
   ```
2. **拖拽后拦截 click**：
   ```js
   function suppressNextClick(el) {
       const handler = (e) => { e.stopPropagation(); e.preventDefault(); };
       el.addEventListener('click', handler, { capture: true, once: true });
       setTimeout(() => el.removeEventListener('click', handler, true), 150);
   }
   ```
3. **定位体系切换无跳变**：基于 `getBoundingClientRect()` 的实际像素位置切换 `right/top` → `left/top`
4. **8px 网格吸附**：`Math.round(value / 8) * 8`
5. **边界约束**：`left ∈ [8, innerWidth - offsetWidth - 8]`
6. **断点切换**：监听 `mqDesktop.change`，桌面端↔移动端自动 `enableAll/disableAll`
7. **位置持久化**：`localStorage.calligraphy_fab_positions`，JSON 格式

## 七、风险评估与回退方案

### 7.1 风险评估

| 风险点 | 概率 | 影响 | 缓解措施 |
|--------|------|------|----------|
| 拖拽时定位从 right/top 切换到 left/top 跳变 | 极低 | 视觉跳动 | 基于 `getBoundingClientRect()` 实际像素位置切换，无跳变 |
| localStorage 位置存储被污染 | 低 | FAB 位置异常 | `Number.isFinite` 校验 + `clampToViewport` 边界约束 + 手动重置按钮 |
| 移动端误触启用拖拽 | 极低 | click 失效 | `matchMedia('(min-width: 681px)')` 检测，移动端不绑定 pointer 事件 |
| 引导浮层遮挡打印按钮 | 中 | 无法打印 | `@media print` 隐藏引导 UI；引导第 2 步就是介绍打印按钮 |
| 老用户被引导打扰 | 极低 | 用户体验 | `localStorage.onboarding_completed` 检查，老用户不弹窗 |
| 桌面端 sidebar-toggle display:none 导致引导异常 | 中 | 引导卡死 | `isElementVisible()` 检查 `offsetParent` 与 `getComputedStyle`，自动跳过不可见步骤 |
| 拖拽与 history-fab 的 hover transform 冲突 | 极低 | 视觉异常 | `.dragging` 类用 `!important` 覆盖 hover 的 `scale(1.1)` |
| `.sh` 在某发行版 `lsof`/`ss`/`netstat` 全不可用 | 极低 | 端口检查失效 | 自动跳到"端口可用"分支，Node.js 启动时自行报 `EADDRINUSE` |
