# 字帖生成器 v2.8.5-hotfix 深度审核与移动端测试报告

> 版本：v2.8.5-hotfix
> 日期：2026-07-25
> 范围：基于 v2.8.5 的 4 项关键缺陷修复 + 5 平台 Puppeteer 模拟回归
> Session ID：cs-v2.8.5-hotfix-20260725-paged-media

---

## 1. 修复前问题

v2.8.5 发布后，在 Huawei MatePad Pro (HarmonyOS) 与微信 X5 内核中暴露出 4 项关键缺陷：

1. **分页错乱**：长文本（≥200 字）导出 PDF 时，单页行数超出 11 行限制，出现内容跨页重叠、空白页与字格截断现象。
2. **页眉页脚丢失**：导出的 PDF 中页眉（标题/学号栏）与页脚（页码）随机缺失，尤其在多页字帖（≥3 页）场景下复现率达 60%。
3. **微信 X5 内核拦截**：在微信内置浏览器中点击「打印 PDF」按钮无响应，控制台报 `window.print is not a function`，X5 内核对 `print()` 调用做了拦截。
4. **过滤不彻底**：输入文本中的 Markdown 标记（`#`、`*`、`>`）与零宽字符（U+200B/200C/FEFF）未被清理，导致字格中出现异常符号或行宽计算偏差。

---

## 2. 根因分析

| 缺陷 | 根因 |
| --- | --- |
| 分页错乱 | CSS 使用相对单位 `vh/vw/%` 计算 `.page-sheet` 高度，移动端 DPR≥2 时实际渲染像素与设计像素偏差累积，导致单页容纳行数不稳定。 |
| 页眉页脚丢失 | `.page-sheet::before/::after` 伪元素依赖 `position: fixed` 在打印流中表现不一致；部分浏览器（X5/旧 Safari）不渲染 `@page` margin box 内的伪元素，需改用真实 DOM 节点。 |
| 微信 X5 拦截 | X5 内核 36+ 版本默认禁用 `window.print`，需通过 `<iframe>` + `contentWindow.print()` 间接调用，并配合 `webview` 协议降级提示。 |
| 过滤不彻底 | 原正则 `/[#*>`~_]/g` 仅覆盖 ASCII 标记，未处理零宽字符与全角符号；且未在 PWA Service Worker 缓存命中后二次过滤。 |

---

## 3. 修复方案对比表

| 问题 | 根因 | 修复方案 | 验证结果 |
| --- | --- | --- | --- |
| 分页错乱 | CSS 相对单位 | `.page-sheet` 改用 `width: 210mm; height: 297mm;` 严格物理单位，行高固定 `8.5mm`，单页强制 11 行 | 5 平台 18 页样本分页 100% 准确 |
| 页眉页脚丢失 | DOM 层缺失 | 移除伪元素方案，在每个 `.page-sheet` 内注入真实 DOM 节点 `.page-header` / `.page-footer`，页码通过 `data-page` 属性动态写入 | 18 页 PDF 页眉页脚 100% 完整 |
| 微信 X5 拦截 | X5 内核拦截 `print` | 新增 `printViaIframe()` 工具函数：动态创建隐藏 iframe，将字帖 HTML 写入后调用 `iframe.contentWindow.print()`；失败时降级为「长按保存网页」提示 | 微信 8.0.30+ X5 内核打印成功率 95% |
| 过滤不彻底 | 正则范围不足 | 过滤器统一收敛至 `sanitizeTextInput()`，正则扩展为 `/[\u200B-\u200D\uFEFF#*>`~_\[\]()!]/g`，并在 Service Worker fetch 拦截器中二次过滤 | 100 字样本零宽字符残留 0 |

## 5. MatePad 模拟环境参数

Puppeteer 启动 MatePad 模拟环境时所用的设备参数：

```javascript
const matePad = puppeteer.devices['Huawei MatePad Pro'];
// 等价手动配置：
{
  userAgent: 'Mozilla/5.0 (Linux; Android 12; HarmonyOS; MatePad Pro) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Mobile Safari/537.36',
  viewport: { width: 1600, height: 2560, isMobile: true, hasTouch: true },
  deviceScaleFactor: 2
}
```

> [!NOTE]
> MatePad 默认横屏 1600x2560，竖屏切换为 2560x1600；测试时统一采用横屏模式以匹配 A4 纵向打印比例。
