## 一、用户反馈的问题与根因分析

### 问题 1：MatePad 上 14 行/页（应为 11 行/页）

| 维度 | 详情 |
|------|------|
| **症状** | 198 字默认文本生成 16 页（应为 18 页），每页 14 行（应为 11 行） |
| **影响** | 拼音与所对应汉字跨页；顶部/底部与 11 格同宽的实线无法保证描绘 |
| **根因** | `print.css` 中 `@media print and (max-width: 900px)` 断点未触发。MatePad 视口 768×1024 DPR=2，实际渲染宽度 1536px > 900px，导致移动端分页规则未应用，回退到桌面默认 min-height:auto |
| **修复** | 将断点从 `900px` 扩展到 `1200px`，覆盖所有移动设备视口 |
| **文件** | [src/styles/print.css](file:///c:/poem2pdf/distribution/src/styles/print.css#L128) |

### 问题 2：MatePad 打印 PDF 时页眉页脚缺失

| 维度 | 详情 |
|------|------|
| **症状** | 通过 MatePad HarmonyOS 打印到 PDF，最终 PDF 中无页眉页脚 |
| **根因** | 与问题 1 同源。`min-height:295mm` 失效后，`.page-section-footer` 的 `margin-top:auto` 无法将页脚推到底部（flex 容器无固定高度时 margin-top:auto 不生效） |
| **修复** | 修复 `min-height:295mm` 后，flex 布局恢复正常，页眉页脚自动定位 |
| **文件** | [src/styles/print.css](file:///c:/poem2pdf/distribution/src/styles/print.css#L216) |

### 问题 3：网格颜色变更后页眉页脚颜色未同步

| 维度 | 详情 |
|------|------|
| **症状** | 修改网格默认颜色后，页眉页脚颜色未跟随变化 |
| **根因** | v2.8.3 已修复（`--grid-primary-color` CSS 变量 + GridEngine.js/settingsCenter.js 双路径同步），v2.8.4 仅验证未回退 |
| **验证** | Group B 确认 [GridEngine.js](file:///c:/poem2pdf/distribution/src/components/GridEngine.js#L606) 第 606-608 行 + [settingsCenter.js](file:///c:/poem2pdf/distribution/src/modules/settingsCenter.js#L63) 第 63-71 行均正确同步 CSS 变量 |

### 问题 4：笔画 SVG 偏移出四线格拼音行

| 维度 | 详情 |
|------|------|
| **症状** | 每行每个字的笔画数及笔顺分解 SVG 图偏移出四线格拼音所在行 |
| **根因** | v2.8.3 已修复（`vertical-align: middle` + `display: block` + flex `align-items: center`），v2.8.4 仅验证未回退 |
| **验证** | Group B 确认 [grid-svg.css](file:///c:/poem2pdf/distribution/src/styles/grid-svg.css#L114) 第 114-125 行 + 第 191-199 行 + [print.css](file:///c:/poem2pdf/distribution/src/styles/print.css#L182) 第 182-190 行（1200px 断点内）均完整保留 |

### 问题 5：CSS 压缩可能丢失 print 规则（潜在风险）

| 维度 | 详情 |
|------|------|
| **症状** | 担心 Vite 构建时 Lightning CSS/esbuild 压缩剥离 `@media print` 关键规则 |
| **根因** | Vite 5.4 默认使用 esbuild 压缩 CSS（非 Lightning CSS），实测未丢失规则，但存在未来合并/简化的潜在风险 |
| **修复** | 在 [vite.config.js](file:///c:/poem2pdf/distribution/vite.config.js#L43) 中显式设置 `cssMinify: false`，作为防御性配置 |
| **验证** | dist/index.html 中 `min-height:295mm`、`page-break-after:always`、`break-after:page`、`max-width:1200px`、`page-break-inside:avoid` 全部保留 |

## 五、HarmonyOS MatePad 打印配置指南

> [!IMPORTANT]
> HarmonyOS 浏览器对打印支持有限，必须按以下配置才能生成正确的矢量 PDF。

### 浏览器选择
- **推荐**：华为浏览器（自带 HarmonyOS 优化）
- **备选**：Chrome for Android（需 Android 10+）
- **禁用**：UC/QQ 浏览器（可能拦截 print 事件）

### 打印设置
| 设置项 | 推荐值 | 原因 |
|--------|--------|------|
| 纸张大小 | A4 | 标准 |
| 方向 | 纵向 | 字帖竖排 |
| 边距 | 默认 | 让 `@page margin: 29mm 15.9mm 16mm 15.9mm` 生效 |
| 缩放 | 100% | 不要缩放，否则破坏 11 行/页 |
| 背景 | **开启** | 打印背景图形，确保网格颜色显示 |
| 页眉页脚 | **关闭** | 浏览器自带页眉页脚与我们的冲突 |

### 保存为 PDF
1. 菜单 → 打印 → 目标打印机选「保存为 PDF」
2. 或菜单 → 分享 → 保存为 PDF（部分 HarmonyOS 版本）

### 常见问题排查
| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 打印预览空白 | 未开启「打印背景图形」 | 设置中开启 |
| 14 行/页 | v2.8.3 断点 900px 未触发 | v2.8.4 已修复（1200px） |
| 页眉页脚缺失 | min-height 失效导致 margin-top:auto 无效 | v2.8.4 已修复 |
| 网格颜色不显示 | 未开启「打印背景图形」 | 设置中开启 |
| 拼音与文字跨页 | page-break-inside:avoid 未生效 | v2.8.4 已修复 |

## 九、GitHub Pages 部署说明

> [!IMPORTANT]
> GitHub Pages 是省钱方案，不是唯一发布路径。但对复赛参赛至关重要，移动端极可能被测试。

### 部署链接（占位符）
- GitHub Pages：`https://stereopensource.github.io/poem2pdf-distribution/`
- GitHub 仓库：`https://github.com/stereopensource/poem2pdf-distribution`

### 部署流程
1. 确保 `npm run build` 生成最新 dist/
2. 将 dist/ 内容推送到 `gh-pages` 分支（或 main 分支的 docs/ 目录）
3. 在 GitHub 仓库 Settings → Pages 中配置源
4. 等待 GitHub Actions 部署完成（约 2-5 分钟）
5. 用 MatePad 打开链接测试

### 替代发布路径
| 路径 | 优点 | 缺点 |
|------|------|------|
| GitHub Pages | 免费、自动部署 | 公开仓库 |
| 本地 npm run preview | 不公开 | 需要本地 Node.js |
| Vercel/Netlify | 免费、CDN 加速 | 需注册账号 |
| 内嵌 HTML 文件 | 离线可用 | 文件较大（3MB） |
