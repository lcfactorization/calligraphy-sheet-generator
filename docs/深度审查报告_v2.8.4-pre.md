# 字帖生成器 深度审查报告 v2.8.4-pre

> **审查日期**：2026-07-25
> **审查背景**：用户实测反馈 v2.8.4 仍存在严重分页问题（MatePad Chrome = 16 页 / Samsung = 15 页），且打印按钮弹窗"请取消勾选页眉页脚"被吐槽多余
> **审查方法**：Puppeteer 模拟 5 个浏览器 + 静态代码审查
> **审查结论**：v2.8.4 的 11 行/页分页策略存在 4 个根因级别缺陷，本报告暂不修改代码，先形成完整诊断

## 二、根因 1：Puppeteer 实测分页也偏差 1 页（19 页 = 18 页 + 1 空白）

### 2.1 现象
我对 5 个视口分别用 Puppeteer 模拟点击打印按钮并导出 PDF，**所有平台都生成 19 页**（多 1 页空白）：

```
MatePad Chrome 768x1024  : 19 页
Samsung Internet 412x915 : 19 页
Kiwi Browser 412x915     : 19 页
Android Chrome 360x800   : 19 页
Desktop Chrome 1280x800  : 19 页
```

### 2.2 根因分析
**`min-height: 295mm` 强制占满整页，导致末页后必多 1 个空白页**。

代码位置：[src/styles/print.css:223](file:///c:/poem2pdf/distribution/src/styles/print.css#L223)

```css
.print-page-section {
    display: flex !important;
    flex-direction: column;
    width: 210mm;
    min-height: 295mm;   /* ← 问题：最后一页内容 < 295mm 时仍占满整页 */
    padding: 8mm 15.9mm 5mm 15.9mm;
    box-sizing: border-box;
    page-break-after: always;  /* ← 问题：即使末页也强制分页 */
    break-after: page;
}
.print-page-section:last-child {
    page-break-after: auto;  /* ← 末页已禁用分页，但 min-height 仍占满空白 */
    break-after: auto;
}
```

**Puppeteer headless 'new' 的 PDF 生成严格遵守 CSS**，所以末页后多 1 空白页是确定的。

### 2.3 用户报告 16/15 页的更严重根因
**Puppeteer 模拟是 19 页（多 1），真实 Chrome 打印对话框是 16 页（少 2）**。差异在 **Chrome 打印对话框默认行为**：

1. **「适合页面」/「Fit to page」选项**：Chrome 打印对话框默认勾选此项，会自动缩放让内容塞进 1 页（少页数）
2. **「边距」默认 Custom 而不是 None**：可能导致 2 页内容被缩到 1 页
3. **真实 MatePad HarmonyOS Chrome 114 vs 桌面 Chrome 120 的 print 引擎差异**：HarmonyOS 版本可能对 `min-height` 处理不同
4. **MatePad Chrome 的 `Save as PDF` 路径与 `window.print()` 路径不同**：可能前者绕过部分 CSS 规则

### 2.4 关键诊断数据
通过 [debug-print-flow.cjs](file:///c:/poem2pdf/distribution/debug-print-flow.cjs) 实测：
- 198 字生成 198 个 `.grid-svg-row` + 198 个 `.grid-svg-aux-row`（正确）
- GridEngine 标记了 17 个 `.page-break`（正确：11×17+11=198）
- printDirect 创建了 18 个 `.print-page-section`（正确：198/11=18）
- 但 Puppeteer PDF 输出 19 页（多 1 空白）

## 三、根因 2：弹窗"请在对话框中取消勾选页眉和页脚"确实多余

### 3.1 弹窗代码位置
[src/utils/pdfExport.js:555](file:///c:/poem2pdf/distribution/src/utils/pdfExport.js#L555)

```javascript
// v2.7.x 优化：alert 改非阻塞 toast，立即调用 window.print()
// 提示用户取消浏览器默认页眉页脚（CSS 无法禁止 Chrome 的页眉页脚选项）
showToast('正在准备打印…请在对话框中取消勾选「页眉和页脚」', 1500);
```

### 3.2 弹窗为何存在
早期 v2.4.5 设计此弹窗，是因为 Chrome 打印对话框有"页眉和页脚"选项，启用后会添加：
- 页眉：日期、标题、网址
- 页脚：页码、网址

这些会与我们的自定义页眉页脚**重复显示**。

### 3.3 为何现在应该取消
1. **用户已熟悉**：v2.8.x 文档中已多次说明"关闭浏览器页眉页脚"
2. **MatePad/三星/Kiwi 浏览器**的打印对话框**没有"页眉和页脚"选项**（仅桌面 Chrome 有）
3. **微信内置浏览器**完全无法打开打印对话框（被拦截）
4. **多余提示造成干扰**：toast 1.5 秒后消失，但可能恰好覆盖打印对话框

### 3.4 修复方向
- 移除该 toast
- 改为静态提示文字（仅在第一次使用时）
- 或改为：检测 `isMobileUA` 时不显示此提示（移动端根本没有这个选项）

## 四、根因 3：移动端浏览器 print 引擎差异

### 4.1 实测对比

| 浏览器 | 行为 | 原因 |
|--------|------|------|
| Desktop Chrome 120 | 分页稳定，遵守 CSS | 完整 print 引擎 |
| MatePad Chrome 114 | 16 页（被压扁） | 缩放默认值不同 + min-height 处理差异 |
| Samsung Internet 23 | 15 页（被压扁更多） | Blink 内核但 print 引擎较旧 |
| Kiwi Browser 120 | 15 页（与 Samsung 接近） | 基于 Chromium 但定制了 print 路径 |
| 微信内置 (X5 内核) | 无打印界面 | X5 拦截 window.print()，需用 JSAPI 唤起 |

### 4.2 关键代码路径分析

#### 4.2.1 `printDirect()` 入口（[pdfExport.js:344](file:///c:/poem2pdf/distribution/src/utils/pdfExport.js#L344)）

```javascript
export function printDirect() {
    // ... 读页眉页脚、创建 wrapper section
    // 动态注入 @page margin:0（覆盖 print.css 的 29mm）
    const pageMarginStyle = document.createElement('style');
    pageMarginStyle.textContent = '@media print { @page { size: A4 portrait; margin: 0 !important; } }';
    document.head.appendChild(pageMarginStyle);
    // ... 调 window.print()
}
```

#### 4.2.2 移动端检测（[pdfExport.js:523-541](file:///c:/poem2pdf/distribution/src/utils/pdfExport.js#L523)）

```javascript
const isMobileUA = /Mobile|Android|iPhone|iPad|iPod|HarmonyOS|HuaweiBrowser|Mobile Safari/i.test(ua)
    && !/Windows NT|Macintosh|CrOS|X11/i.test(ua);
const isHarmonyOS = /HarmonyOS|HuaweiBrowser/i.test(ua);
console.log('[pdfExport] 移动端检测: isMobileUA=', isMobileUA, 'isHarmonyOS=', isHarmonyOS);

if (isMobileUA) {
    const hint = isHarmonyOS
        ? '📱 MatePad/华为手机用户：建议点击浏览器底部 ∷ 菜单 → 保存 PDF（或 更多 → WPS 网页转 PDF），效果更佳。即将打开打印对话框…'
        : '📱 移动端建议使用浏览器菜单 → 网页转 PDF / 保存为 PDF。即将打开打印对话框…';
    showToast(hint, 6000);
}
```

**问题**：MatePad 用户看到的也是这个 6 秒 toast，但**用户已经按了打印按钮**——再提示"用浏览器菜单"已无意义。

#### 4.2.3 微信内置浏览器失败原因
- 微信 X5 内核（基于 Blink）**拦截 `window.print()`**（无权限调起原生打印）
- 应改为：检测到微信时直接隐藏打印按钮，提示"请用浏览器打开"或自动跳转外部浏览器

## 五、根因 4：CSS 缺乏 @page margin 与真实打印设置的协作

### 5.1 print.css 现状
```css
@page {
    size: A4 portrait;
    margin: 29mm 15.9mm 16mm 15.9mm !important;  /* Puppeteer 路径用 */
}
```

```css
.print-page-section {
    min-height: 295mm;
    padding: 8mm 15.9mm 5mm 15.9mm;  /* window.print() 路径用 */
}
```

### 5.2 问题
- **@page margin = 29mm**（顶部 29mm 给 Puppeteer headerTemplate）
- **.print-page-section padding-top = 8mm**（给 window.print 用）
- **两者叠加**：`29mm + 8mm = 37mm` 的顶部空间

但 `@page margin: 29mm` 只在 Puppeteer 路径生效，printDirect 路径动态注入 `margin: 0` 覆盖了。

### 5.3 真实 Chrome 打印对话框的"魔法"
即使 CSS 中 `@page margin: 0` 被注入，**Chrome 打印对话框的「边距」设置仍会附加**：
- 默认「默认」选项：留 4mm 边距
- 「无」选项：留 0mm
- 「最小」选项：留 1mm
- 「自定义」：用户输入

用户如果保留默认 4mm 边距，内容会被压缩（**这是用户报告 16/15 页的最可能根因**）。

### 7.1 [src/styles/print.css:223] `.print-page-section` min-height 缺乏条件

### 7.3 [src/utils/pdfExport.js:536-541] 移动端提示过于啰嗦
```javascript

    const hint = isHarmonyOS ? '...' : '...';

```

**建议**：用户已点打印按钮，提示"用浏览器菜单"已无意义。删除或简化为"正在准备打印…"。

### 7.4 [src/main.js:66] 打印按钮未检测微信
```javascript

```

**建议**：在 exportPDF 内部检测微信 UA，提示"请用浏览器打开"或跳转。

### 7.5 [src/styles/print.css:225-228] page-break-after: always 末页处理不彻底
```css
.print-page-section {
    page-break-after: always;  /* 所有 section 都强制分页 */
}
.print-page-section:last-child {
    page-break-after: auto;  /* 仅最后取消 */
}
```

**问题**：当 wrapper 不在 DOM 树最后时，`:last-child` 可能匹配错误。

### 7.6 [src/utils/pdfExport.js:505] 动态 @page margin 注入
```javascript
pageMarginStyle.textContent = '@media print { @page { size: A4 portrait; margin: 0 !important; } }';
```

**问题**：注入时机在 afterprint 之前，但 Chrome 实际打印可能不严格遵守此 CSS。

### 7.7 @media print and (max-width: 1200px) 断点范围仍可能不够
Puppeteer 测试中 `matchMedia('print and (max-width: 1200px)').matches` 返回 true（视口 768 < 1200）。**但 MatePad 真实设备的视口宽度由 viewport meta 决定**，可能为 1024-1280。如果 viewport meta 设为 1280+ 仍会超出 1200px 断点。

## 九、可能的真正根因（综合分析）

### 9.1 假设 A：Chrome 打印对话框的"适合页面"功能
- **可能性**：高
- **证据**：用户报告 16 页（少 2），而 Puppeteer（无 fit-to-page）= 19 页（多 1）。真实 Chrome 启用 fit-to-page 后可能把 2 页内容缩到 1 页
- **验证方法**：在 print 预览中**取消 fit-to-page**（设为 100% 缩放）后再打印

### 9.2 假设 B：min-height: 295mm 触发空白页
- **可能性**：高（Puppeteer 已确认多 1 空白）
- **证据**：所有 Puppeteer 平台 = 19 页（= 18 + 1 空白）
- **验证方法**：临时移除 min-height，看是否变 18 页

### 9.3 假设 C：移动端 print 引擎对 min-height 处理不同
- **可能性**：中
- **证据**：MatePad 16 页 vs Desktop 18 页（差 2 页），可能是 min-height 被忽略后内容被 fit-to-page 压扁
- **验证方法**：在 MatePad 实测，取消 fit-to-page + 强制 100% 缩放

### 9.4 假设 D：浏览器版本差异
- **可能性**：中
- **证据**：Chrome 114 (MatePad) vs Chrome 120 (Desktop) 的 print 引擎实现不同
- **验证方法**：用 Chrome 114 Desktop 模拟，看分页是否变 16 页

## 十、修复方向建议（待用户确认后再实施）

### 10.1 短期修复（必做）
1. **删除多余 toast**：[pdfExport.js:555](file:///c:/poem2pdf/distribution/src/utils/pdfExport.js#L555) 直接删除
2. **简化移动端提示**：[pdfExport.js:536-541](file:///c:/poem2pdf/distribution/src/utils/pdfExport.js#L536) 简化为"正在准备打印…"
3. **末页 min-height 自适应**：修改 `.print-page-section:last-child` 允许 min-height: auto
4. **微信浏览器检测**：在 main.js / exportPDF 中检测 MicroMessenger UA，提示跳转

### 10.2 中期修复（分页核心）
1. **改用 jsPDF 路径作为默认**：放弃 window.print() 路径，因为不可控因素太多
2. **或在 Puppeteer 路径默认启用**：v2.8.x 已支持 puppeteerClient.js，但需要本地启动 Node.js 服务
3. **强制 fit-to-page 关闭**：CSS `@page { size: A4 portrait; }` 不带 margin，加上 `marks: none;` 关闭裁切标记

### 10.3 长期方案
1. **PWA + 纯前端 jsPDF 导出**：避开浏览器 print 引擎的不可控性
2. **service-worker 后台预渲染 PDF**：用户打开应用时即准备好
3. **WebAssembly 字体引擎**：保证跨平台字体渲染一致性
