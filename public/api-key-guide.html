一、功能概述

v1.1.0v3.0.4字帖的 AI 辅助功能提供组词补齐、拼音纠错与全量检查三项能力，支持 16 家大模型引擎（唯一注册表：src/modules/aiProviders.js）：

  • AI 组词补齐：对默认词库缺失二字组词的汉字，调用大模型补齐 2 个二字词
  • 拼音纠错：核对多音字 / 误读拼音并纠正（自动升级强模型深度校验）
  • 全量检查：核验所有未缓存字的拼音 / 语义 / 已有组词（优先级最高，联动其余两项）
  • 自动选择引擎：默认「自动选择（推荐）」，应用逐个探测已保存的 Key，自动挑选最可用的引擎并优先免费引擎，无需用户手动选择
  • 本地存储：Key 仅保存在浏览器 localStorage，调用记录与结果缓存在本地，不上传任何服务器
提示：AI 辅助为可选功能，不配置 Key 时字帖所有核心功能（生成 / 打印 / 笔顺演示等）完全不受影响。

二、快速开始

  1. 点击右上角「⚙️ 设置中心」→ 找到「🤖 AI 辅助（可选）」区块
  2. 在「＋ 添加」输入框粘贴任意受支持引擎的 API Key（如 DeepSeek 的 sk- 开头、火山引擎豆包的 ark- 开头），点击「＋ 添加」
  3. 勾选功能开关：组词补齐（默认）/ 拼音纠错 / 全量检查（级联联动）
  4. 点击「▶ AI 检查与补齐」运行，状态栏显示旋转图标 + 批次进度
说明：v3.0.1 起 Key 采用「添加即生效」机制，无需再点「保存」按钮；v3.0.4 起添加或导入后自动探测（识别引擎 + 判定可用性 + 是否免费）并纳入自动优选，无需任何手动步骤。

3.2 多 Key 存储与自动选择

  • 设置面板可存储多个 API Key（localStorage key：ai_api_keys，JSON 数组）
  • ≥2 个 Key 时显示引擎下拉选择器，首位为「自动选择（推荐）」且默认选中：应用探测每个 Key 后自动挑选最优引擎并优先免费引擎，用户无需自己选择；选项格式：DeepSeek · sk-1234…abcd（引擎 + Key 前 4 后 4 打码）
  • 手动在下拉中选中某个具体 Key → 固定为手动模式；重新选择「自动选择」→ 回到自动模式（写入 ai_active_key_id，无需保存）
  • 单个 Key 时不显示下拉（保持简洁）；删除当前活跃 Key 后自动切换到剩余第一个
  • Key 展示框右侧 👁 眼睛按钮可切换显示 / 隐藏，🗑 按钮删除当前 Key

3.3 从文件导入 Key

  • 导入按钮：📂 从文件导入 Key（设置面板 AI 配置区内）
  • 支持格式：.txt / .md / .csv / .docx（含 Word 文档，自动解析 document.xml）
  • 导入逻辑：按注册表各引擎的 pattern 正则提取文件中的 Key（sk- / ark- / sk-or-v1- / sk-apx / ms- / AIzaSy / gsk_ / bce-v3/ALTAK- 等），去重后全部入库
  • 导入后自动批量探测并优选（v3.0.4）：自动识别引擎、判定可用性、纳入「自动选择」候选
  • 导入完成提示：「✓ 已导入 N 个 Key（当前生效：×××）」，并刷新下拉选择器
  • 文件内容仅在浏览器本地解析，不会上传

3.4 自动识别与消歧（v3.0.4）

  • 添加 / 导入 Key 后自动探测：识别所属引擎、判定可用性、标注是否免费，并自动纳入优选，无需手动操作
  • 形状唯一的 Key 直接判定：如 ark- → 火山引擎豆包，sk-or-v1- → OpenRouter，sk-apx → APINEX，ms- → ModelScope 魔搭，AIzaSy → Google Gemini，gsk_ → Groq
  • 形状歧义的 Key 自动消歧（本次头号改进）：sk- 前缀被 DeepSeek / 月之暗面 Kimi / 硅基流动 / 阿里云百炼 / Agnes AI共用，仅凭字符串无法判定路由；应用按候选引擎逐个探测、命中即止，并把命中的引擎回写保存，用户无需手动选择
  • 形状完全未知的 Key：用「零 token 且会校验鉴权的 /models」端点做免费扫描，避免浪费额度
  • 少数无稳定形状的引擎（阶跃星辰 / 腾讯混元）需在设置中手动指定引擎后再检测
  • 模型逃生门：若线上模型 ID 失效（403/404），可在浏览器控制台执行 localStorage.setItem('ai_model_override_<引擎ID>', '正确的模型名') 换模型，无需重新打包（v3.0.4 起按引擎作用域；旧的全局键 ai_model_override 仅对 DeepSeek / 火山引擎生效）

3.5 「🔍 检测全部 Key 可用性」（v3.0.4）

设置中心新增该按钮，逐个探测已保存的 Key 并显示徽章结果。探测分两阶段：

  1. 阶段 1（零 token）：GET /models 鉴权快路径 —— 仅对「该端点确实校验鉴权且带 CORS 头」的引擎启用，不消耗额度
  2. 阶段 2（3 token）：max_tokens: 3 的 chat 能力探测，校验应用真正要发送的那个模型 ID；若引擎不支持 response_format: json_object，会自动去掉该字段重试一次并降级记录。引擎拒绝 response_format 有两种方式，都会被处理：(1) 规范的 400/422 + 错误文本；(2) 不合规的 200 但响应体退化（如 {"choices":null}，实测 ModelScope 的 Qwen/Qwen3.8-Flash-Next 在 3 token 下即如此）—— 后者若不重试，会把真实可用的引擎误报为「走了代理或 baseUrl 配置错误」
徽章 含义
✓免费 探测成功，且使用的是免费档（tier: free）模型
✓可用 探测成功（付费 / 低价档模型）
⚠限流 HTTP 429，请求过于频繁；Key 仍然可用，不会被标记为失效
⚠不可达 网络或浏览器跨域（CORS）限制导致无法连接；文案会明确提示「可能是跨域限制」
✗Key无效 HTTP 401，Key 无效或已过期
✗额度耗尽 HTTP 402 / 403，额度不足或无该模型权限（歧义状态，不判定为 Key 无效）
✗模型不存在 HTTP 404，模型 ID 不存在或未开通，需在注册表中更换模型
说明：探测串行执行（并发 1），单个约 8 秒超时，裁决缓存 30 分钟；离线时跳过探测并保留上次结果。探测结果仅用于本地选择，不会上传。
自动优选的评分依据：0.30×免费度 + 0.20×速度 + 0.25×JSON稳定性 + 0.25×历史成功率 − 额度风险，并列时按「延迟升序 → 引擎优先级 → 创建时间」决胜。
关于「速度」的诚实说明：探测只有 3 token，对推理型模型毫无代表性——推理模型在 3 token 下秒回，真实组词负载下却会先生成大量 reasoning token。实测同一任务（4 字全量检查）：Agnes 约 13 秒，ModelScope 约 100–120 秒（约 8–9 倍），而两者探测延迟反而是 ModelScope 更快。因此注册表支持 slow 标记（仅对实测过的模型设置），标记后该项不再由失真的探测延迟给分，避免自动优选选中"探测快、实际慢"的引擎。

四、引擎路由与调用流程

  1. 引擎路由：默认「自动选择（推荐）」——系统探测并消歧后确定活跃 Key 所属引擎，优先免费且稳定的引擎；手动选中某个 Key 时按该 Key 固定路由，无需手动切换
  2. 分批处理：待处理汉字按每批 ≤10 字分组，逐批调用大模型 API，支持中断（运行中按钮变为「⏹ 中断」）
  3. 进度提示：状态栏显示蓝色旋转图标 + 批次进度（如「正在补齐 [DeepSeek]… 10/20 字（批次 1/2）」）
  4. 结果解读：完成后显示「✓ DeepSeek：共 X · 默认 X · AI X · 缺失 X（Xms）」；开启拼音纠错还会列出纠错明细（原拼音 → 纠正拼音 + 原因）
  5. 缓存机制：已写入 AI 缓存的字（ai_zuci_cache_v1）自动跳过，避免重复消耗；如需重查可执行 localStorage.removeItem("ai_zuci_cache_v1") 清缓存
  6. 概率属性：AI 回答具有概率性，少数情形一次未必能覆盖全部；多重复点击几次可逐步补齐 / 纠错全部
可靠性：5 分钟硬超时 + 3 次重试；错误码提示——401 无效 Key、403 无模型权限 / 额度耗尽、429 请求过频（等待 30 秒重试）。

五、安全与隐私

  • API Key 仅存储在浏览器 localStorage（ai_api_keys + ai_active_key_id）
  • Key 不会发送到任何第三方服务器，仅直接调用所选引擎的官方 API
  • 旧版单 Key（deepseek_api_key）在首次使用时自动迁移到新结构（幂等，迁移成功才删除旧键）
  • 建议：不要在多用户共用的电脑上保存 Key，或使用浏览器「退出时清除此站点数据」功能

六、常见问题

Q1：Key 保存后显示「验证失败 / 401」？

先点「🔍 检测全部 Key 可用性」查看具体原因：✗Key无效 表示 Key 过期，✗额度耗尽 表示余额不足，⚠不可达 表示网络不通或浏览器跨域（CORS）受限。同时确认网络可访问对应引擎的 API 域名。

Q2：文件导入找不到 Key？

确保文件内容包含完整的 Key（形状见 3.1 表格，如 sk- / ark- / sk-or-v1- / AIzaSy / gsk_ 开头、前后无截断），支持多行 / 多 Key；docx 需含正文文本（解析 word/document.xml）。

Q3：如何切换当前生效的 Key？

默认使用「自动选择（推荐）」，无需手动切换；如需指定，≥2 个 Key 时在设置面板下拉中选中某个具体 Key 即固定为手动模式，重新选择「自动选择」即回到自动模式。删除活跃 Key 后自动切换到剩余第一个。

Q4：如何删除已保存的 Key？

打开设置中心 → 点击 Key 展示框右侧 🗑 删除当前 Key；删空后自动清空两把存储键。也可用浏览器开发者工具 → Application → Local Storage → 删除 ai_api_keys / ai_active_key_id。

Q5：豆包报 403？

无该模型权限或额度耗尽，请更换模型（见 3.4 逃生门）或充值；全量检查使用的 Turbo 模型可能需单独开通权限。
